These are the stores and brokers along the bottom of the [system overview](/system-overview) diagram. A first install starts the defaults for you. This page is what each one is *for*, and when you would switch.

Read it in the same order as the diagram: search data, application data, then how services talk and where config lives.

## Knowledge graph (Neo4j or ArangoDB)

The graph is how PipesHub remembers that a Slack thread, a Drive file, and a person belong together. Permissions and citations walk those links.

You pick one database with `DATA_STORE`. Services go through a graph abstraction, not a Neo4j or ArangoDB driver, so the product behaves the same on either.

- **Neo4j** is the default (`DATA_STORE=neo4j`). That is what a first install, `backend/env.template`, and the Helm chart use.
- **ArangoDB** is the other option (`DATA_STORE=arangodb`). Existing installs that already have an ArangoDB volume keep it.

[Neo4j](https://neo4j.com/) · [ArangoDB](https://www.arangodb.com/)

## Vector search (Qdrant)

After Indexing parses a document, an embedding model turns each chunk into a vector. **Qdrant** stores those vectors and finds similar text when Query answers a question.

Qdrant is what a first install runs (`VECTOR_DB_TYPE=qdrant`).

[Qdrant](https://qdrant.tech/)

## Application data (MongoDB)

MongoDB holds things that are not the knowledge graph: sessions, file metadata, and other application state.

[MongoDB](https://www.mongodb.com/)

## Files

File *bytes* are not in MongoDB. They live on local disk or in object storage (S3, Azure Blob, GCS), behind the [storage](/system-overview/storage) module in the API.

## How services hand work to each other

Connectors publish records; Indexing consumes them. That path is the **event bus** in the diagram.

- On a **local machine**, the bus is **Redis Streams** (`MESSAGE_BROKER=redis`). Kafka is not started.
- In a **larger deployment**, the bus is **Kafka** (`MESSAGE_BROKER=kafka`).

The Python services do not change. Only the transport does.

[Apache Kafka](https://kafka.apache.org/)

## Cache, config, and Redis

**Redis** is always on. It does three jobs, depending on how you deploy:

1. **Cache** — hot data and locks
2. **Encrypted config** — the default key-value store for settings (`KV_STORE_TYPE=redis`)
3. **Event bus** — Redis Streams, when `MESSAGE_BROKER=redis`

In a larger deployment Kafka takes over the bus. Redis stays as cache, and as the config store unless you switch KV to etcd.

[Redis](https://redis.io/)

## Optional: etcd

etcd is the other place to keep encrypted configuration. A laptop install does not start it.

Turn it on with `KV_STORE_TYPE=etcd` and the Compose profile `kv-etcd`.

[etcd](https://etcd.io/)
