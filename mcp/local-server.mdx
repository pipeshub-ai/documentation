Instead of connecting to PipesHub's remote MCP endpoint, you can run the MCP server locally as a stdio process using the `@pipeshub-ai/mcp` npm package. This is useful when you prefer a local setup or need to work in environments where direct HTTP connections to the remote MCP endpoint aren't practical.

## Prerequisites

- Node.js 20+ installed
- A PipesHub instance URL
- A credential that acts as you, so results follow your permissions: a `pipeshub login` sign-in (no token in any config, below) or a **[Personal Access Token](/developer/personal-access-tokens)**

<Tip>
  No instance yet? Start on [PipesHub Cloud](https://app.pipeshub.com/?ref=docs), or self-host with the [Local Docker demo](/for-agents-local-demo), then come back here. Do not scaffold LangChain.
</Tip>

<Tip>
  For the `--bearer-auth` flag used throughout this page, a [Personal Access Token](/developer/personal-access-tokens) is the easiest option: create one under **Developer Settings > Personal Access Tokens** and use it directly — no OAuth app, redirect URIs, or token exchange required.
</Tip>

## No token in the config

With `@pipeshub-ai/mcp` 4.7.0 or later, sign the CLI in once and let it write the client entry:

```bash
npm i -g @pipeshub-ai/mcp
pipeshub login                     # PipesHub Cloud; add --url <origin> when self-hosted
pipeshub mcp install --client cursor   # or claude-code, codex, gemini, claude-desktop
```

Restart the client. The entry runs `npx -y @pipeshub-ai/mcp@>=4.7.0 start --server-url <origin>` with no `--bearer-auth`: the local server uses the `pipeshub login` sign-in and refreshes it, so no token is written into the client's config. An agent setting this up runs `pipeshub login --no-wait`, gives the user the link and code, then `pipeshub login --wait`. `--dry-run` shows what `mcp install` would change, and `--force` replaces an existing `pipeshub` entry.

The sign-in keeps refreshing on PipesHub versions that give device logins a refresh token; on older ones it lasts an hour. With no `--bearer-auth` and no sign-in, `start` also accepts `PIPESHUB_TOKEN` from the environment, sent only to `--server-url` or `PIPESHUB_BASE_URL`.

The "Signed in" tabs below are the same entries written by hand.

## Placeholders

Replace these in all configurations below:

| Placeholder | Description | Example |
|---|---|---|
| `PIPESHUB_API_URL` | Your PipesHub instance URL followed by `/api/v1` | `https://app.pipeshub.com/api/v1` |
| `YOUR_BEARER_TOKEN` | [Personal access token](/developer/personal-access-tokens) (or any other Bearer JWT) | `phpat_eyJhbGci...` |

## Cursor

Open **Cursor Settings > Tools and Integrations > New MCP Server**, or edit your project's `.cursor/mcp.json`:

<CodeGroup>
```json Bearer token
{
  "mcpServers": {
    "pipeshub": {
      "command": "npx",
      "args": [
        "-y",
        "@pipeshub-ai/mcp",
        "start",
        "--server-url",
        "PIPESHUB_API_URL",
        "--bearer-auth",
        "YOUR_BEARER_TOKEN"
      ]
    }
  }
}
```

```json Signed in (no token)
{
  "mcpServers": {

}
```

## Running from Source (Development)

To run the local MCP server from a cloned repository instead of the npm package:

```bash
git clone https://github.com/pipeshub-ai/mcp-server.git
cd mcp-server
npm install
npm run build
node ./bin/mcp-server.js start --server-url PIPESHUB_API_URL --bearer-auth YOUR_BEARER_TOKEN
```

For MCP client configuration, replace `npx @pipeshub-ai/mcp` with `node ./bin/mcp-server.js`:

```json
{
  "mcpServers": {
    "pipeshub": {
      "command": "node",
      "args": [
        "./bin/mcp-server.js",
        "start",
        "--server-url",
        "PIPESHUB_API_URL",
        "--bearer-auth",
        "YOUR_BEARER_TOKEN"
      ]
    }
  }
}
```

To debug with MCP Inspector:

```bash
npx @modelcontextprotocol/inspector node ./bin/mcp-server.js start --server-url PIPESHUB_API_URL --bearer-auth YOUR_BEARER_TOKEN
```

## Retries and timeouts

The local server (`start` and `serve`) waits out short outages on requests that are safe to repeat:

- A request refused with **429**, **502**, **503** or **504** is retried, three tries in all. The server waits as long as PipesHub's `Retry-After` header asks, or, without one, about half a second and then a second.
- A `Retry-After` longer than 30 seconds isn't waited out. The tool's error says how long PipesHub asked to wait instead.
- Only `GET`, `HEAD`, `OPTIONS`, `PUT` and `DELETE` requests are retried. Search and chat are `POST` requests and are never retried, because a repeat would be a second search or a second answer.
- Each try that gets no response within 60 seconds is abandoned. The limit covers the wait for PipesHub to start answering, so a long chat answer that is already streaming is not cut off. The limit applies to each try, not to the whole call. A try that gets no answer at all ends the call without a retry, but when slow tries end in a 429, 502, 503 or 504 and are retried, a `GET`, `PUT` or `DELETE` can take up to about three minutes at the defaults (three tries plus the waits between them). Search and chat get one try.

When a call fails because PipesHub can't be reached, the tool's error names the address, gives the reason (for example a refused connection or an untrusted certificate), and says to check the `--server-url` or `--instance-url` the server was started with. When a call times out, the error says to try again, check that PipesHub is healthy, or raise `PIPESHUB_MCP_TIMEOUT_MS`. The request's bearer token (if it is at least eight characters) is removed from the body of any 4xx or 5xx response before the model sees it. Error text inside a successful streamed answer is passed on as it is.

Change the defaults with environment variables, in your MCP client's `env` block or with `--env NAME=VALUE`:

| Variable | Default | Meaning |
|---|---|---|
| `PIPESHUB_MCP_MAX_ATTEMPTS` | `3` | Tries per request, the first one included, from 1 to 10. `1` turns retries off. |
| `PIPESHUB_MCP_TIMEOUT_MS` | `60000` | Milliseconds to wait for PipesHub to start answering, up to `3600000` (one hour). `0` turns the timeout off. |

```json
{
  "mcpServers": {
    "pipeshub": {
      "command": "npx",
      "args": [
        "-y",
        "@pipeshub-ai/mcp",
        "start",
        "--server-url",
        "PIPESHUB_API_URL",
        "--bearer-auth",
        "YOUR_BEARER_TOKEN"
      ],
      "env": {
        "PIPESHUB_MCP_TIMEOUT_MS": "120000"
      }
    }
  }
}
```

A value that isn't a whole number in these ranges is refused, with a message saying what it must be.
