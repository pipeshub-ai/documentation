After [`init`](/mcp/standalone/quickstart), Gemini CLI can search your team's documents and, once you have indexed a repository, ask about its code. This page covers what `init` changes for Gemini CLI and how to check it.

## What `init` writes

| File | What |
|---|---|
| `~/.gemini/settings.json` | The `pipeshub` entry under `mcpServers` |
| `~/.gemini/GEMINI.md` | A PipesHub section between `pipeshub:begin` and `pipeshub:end` markers: when to use search, the code tools and `index_workspace` |
| `~/.gemini/commands/pipeshub/index.toml` | `/pipeshub:index` |
| `~/.gemini/commands/pipeshub/code.toml` | `/pipeshub:code <question>` |

## Check that Gemini CLI sees PipesHub

<Steps>
  <Step title="Start a new session">
    Run `gemini` again.
  </Step>
  <Step title="List the servers">
    Run `/mcp` in the session. `pipeshub` should show as connected with its tools. `gemini mcp list` shows the same from a terminal.
  </Step>
  <Step title="Index and ask">
    Run `/pipeshub:index`, then `/pipeshub:code what calls the main entry point?`.
  </Step>
</Steps>

## Without `init`

Start the stack and sign in first ([Set up one agent by hand](/mcp/standalone/quickstart#set-up-one-agent-by-hand)), then add the entry to `~/.gemini/settings.json`:

```json
{
  "mcpServers": {
    "pipeshub": {
      "command": "npx",
      "args": ["-y", "@pipeshub-ai/mcp@>=4.8.0", "start", "--server-url", "http://127.0.0.1:3000"],
      "env": { "PIPESHUB_MCP_CHAT": "off" }
    }
  }
}
```

This is the local setup. To connect Gemini CLI to a hosted PipesHub, see [Gemini CLI](/mcp/gemini-cli).

## Undo

```bash
npx @pipeshub-ai/standalone uninstall --client gemini
```

This removes only what `init` added for Gemini CLI, from the files above. A backup of each file `init` changed is in `~/.config/pipeshub/backups/`. To remove everything, see [Undo everything](/mcp/standalone/quickstart#undo-everything).
