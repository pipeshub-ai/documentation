## Current status

Google Forms is registered as a **beta connector definition**. It appears in the connector catalogue and has a complete OAuth configuration, but the sync itself is not implemented.

<Warning>
**This connector does not index anything yet.** Its definition sets
`with_sync_support(False)` (`core/registry/connector.py:410`), and `FormsConnector.connect()` is a placeholder that
returns without contacting the API. Setting it up will not make Google Forms content
searchable in PipesHub.
</Warning>

The definition is present so the connector appears in the catalogue and its OAuth
application can be registered ahead of the sync implementation landing. It is also
gated behind the beta connector registry, so it only appears when beta connectors
are enabled for your deployment.

## What works today

Nothing in this connector reaches Google Forms yet. If you need form data now,
the practical option is the [Google Drive connector](/connectors/google-workspace/drive/drive):
forms are stored as Drive files, so a form's structure is indexed along with the
rest of your Drive content. Responses are not — those live in the Forms API, which
only this connector will reach.

## For when it ships

The OAuth application it will use is already defined, so this part is stable and
worth setting up in advance if you are preparing an environment.

Google Forms requires **two** Google APIs enabled, not one:

- **Google Forms API**
- **Google Drive API** — forms are stored as Drive files and are discovered through Drive

Enabling only the obvious one is the common mistake, and it fails quietly.

The redirect URI ends with the capitalised connector name and must be registered
exactly as PipesHub displays it.
