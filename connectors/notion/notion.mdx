## Overview

PipesHub has two Notion connectors. Both sync **pages**, **databases**, **comments**, and **file attachments** from the pages you share with the connection. They use the same Notion developer setup, but they do **not** share the same audience in search.

| Connector | Where you set it up | Who can search the synced records |
|-----------|---------------------|-----------------------------------|
| **Notion** (team) | **Workspace Settings → Connectors → Notion** | Every Notion workspace member PipesHub can map by email - **not** only the people a page is shared with in Notion |
| **Notion Personal** | **Workspace Settings → Your Connectors → Notion Personal** | **Only you** (the person who created the connector) |

<Warning>
  **Team connector limitation:** Notion's API does not expose per-page sharing, so the team connector **does not follow Notion ACLs**. Anything it syncs becomes searchable by everyone in that Notion workspace (matched in PipesHub by email). Private or restricted pages you share with the integration are visible to those users in PipesHub, even if they could not open the page in Notion. Use **Notion Personal** if the content should be searchable only by you.
</Warning>

<Note>
  The team connector identifies people by **email**: workspace members get access to the synced set when they sign in to PipesHub with the **same email** they use in Notion. Notion Personal does not need a matching email. The PipesHub user who created the connector is its only audience.
</Note>

### What gets synced

| Entity | Description |
|--------|-------------|
| **Pages** | Pages you grant during OAuth (or share with an internal connection), including their blocks |
| **Databases** | Database properties and rows in scope (Notion data sources) |
| **Files** | Attachments on pages and comment attachments (when **Index Files** is on) |
| **Comments** | Comments on shared pages, when the connection can read comments |
| **Users** | Team connector only - workspace people used to grant search access. Notion Personal does not sync a user directory |

The connector only sees content Notion granted it. **Configure Records** in PipesHub can narrow indexing further; it cannot reach pages you never shared.

### Authentication

| Method | Team (**Notion**) | **Notion Personal** |
|--------|-------------------|---------------------|
| **OAuth** (New connection → OAuth) | Yes - redirect path ends with `/Notion` | Yes - redirect path ends with `/Notion%20Personal` |
| **Access token** (`ntn_...`) | Yes - same **New connection** dialog, **Access token** method | No |
| **Personal access tokens** (Developer tools tab) | Not supported | Not supported |

In PipesHub the OAuth flow has three tabs: **Authenticate Instance** (Redirect URL + client credentials), **Authorize** (sign in to Notion and pick pages), then **Configure Records** (sync strategy and indexing).

## Configuration Guide

In Notion, open **Settings → Connections → Go to developer portal**, create a connection, copy the **Redirect URL** from PipesHub into that connection (OAuth only), then finish setup in PipesHub.

### How to configure and enable the connector

1. Open your **user profile** menu (bottom of the left sidebar) → **Workspace Settings**.
2. Choose the catalog that matches the access model you want:
   - **Team** - under **Workspace**, select **Connectors**. Find **Notion** and click **+ Setup**.
   - **Personal** - under **Personal**, select **Your Connectors**. Find **Notion Personal** and click **+ Setup**.

- Personal: `https://{your-pipeshub-host}/connectors/oauth/callback/Notion%20Personal`

Use the value shown in PipesHub (scheme, host, and path). The two connectors need **different** redirect URIs. You can register both on one public connection, or create a separate public connection for each.

### Team alternative: internal connection

The **team** connector can use an **Access token** (Internal Integration Secret) instead of OAuth. Notion Personal does not support this. Tokens from the **Personal access tokens** tab in Developer tools are **not** accepted - the workspace is identified from the connection's bot user.

1. Follow [Step 3](#step-3-open-notions-developer-portal) and click **+ New connection**.
2. Choose **Access token** (workspace-scoped static API token, one workspace). Fill **Connection name** and create the connection. Redirect URIs are not used.
3. On the connection page, copy the **Access token** (`ntn_...`) and set the same **Capabilities** as Step 5 (read content, read comments, user email).

<div className="text-center">
  <img
    src="/images/connectors/notion/notion-connector-connection-permissions.png"
    alt="Notion access-token connection - Access token and required capabilities"
    className="block mx-auto w-11/12"

4. Grant page access: **Content access** on the connection, or in Notion **••• → Connections → + Add connection** on each page or parent you want synced. Child pages inherit access.
5. In PipesHub, on **Authenticate Instance**, choose the internal-secret auth option, paste the token, and continue to **Configure Records** (there is no Notion OAuth page picker).

## Access and permissions

| | **Notion** (team) | **Notion Personal** |
|--|-------------------|---------------------|
| **Who can search** | All Notion workspace members PipesHub maps by email | Only the connector creator |
| **Follows Notion page sharing / ACLs** | No. Notion's API does not expose per-page sharing | No per-page ACL either - but the only audience is you |
| **User directory** | Synced so those members can be granted access | Not synced |
| **How to widen or narrow content** | Share more or fewer pages with the connection (OAuth picker or internal **Content access**) | Same - only the pages you share during authorization |

## Current limitations

Each sync uses Notion's Search API and reads the pages and databases whose **`last_edited_time`** is newer than the last successful run, plus a ten-minute overlap. At the end of every sync, PipesHub also compares what it holds with everything the connection can see now:

- Pages and databases shared with the connection later are synced, even if nobody edited them.
- Pages and databases that are deleted, moved to the trash, unshared, or moved under a page the connection cannot see are removed from PipesHub.

A record is removed only when Notion confirms the page is gone or in the trash. If Notion returns an error or the listing does not finish, nothing is removed that run and the next sync tries again.

| Situation | What a sync does | What to do |
|-----------|------------------|------------|
| **Move** a page or database to a new parent that the connection can still see (no content edit) | Usually nothing. A move alone often does not update `last_edited_time`, and Notion has no API for move events. | Edit the page or database, or run **Full sync**. |
| **Add or delete a comment** | Notion does not update a page's `last_edited_time` for comments. Each sync rechecks the comments of a slice of pages, so a change is picked up within about 24 syncs (about a day at the default 1-hour interval; longer on very large workspaces). | Edit the page, or run **Full sync**, if you need it sooner. |

Other limits that come from the same Notion API:

- **No per-page ACLs on the team connector.** See [Access and permissions](#access-and-permissions). Notion does not return who a page is shared with.
- **Not realtime.** There is no webhook-driven sync. Changes appear on the next scheduled run, a manual **Sync**, or a **Full sync**.
- **Size limits.** Images added by URL are fetched up to **20 MB**, and files added by URL up to **100 MB**. Larger ones are not indexed.
- **Only pages the connection can see.** Search never returns content you did not share with the integration.
- **Rate limit.** Notion allows about **3 requests per second** per integration. Large pages need many block fetches, so the first sync of a big workspace can take a long time.
- **Images are not separate files.** Inline images stay on the page (and may be inlined for indexing). **Index Files** covers file, video, PDF, and audio attachments - not image blocks.
- **Users without email.** The team connector maps workspace members by email. A member who hides their email in Notion is not granted access, but keeps any access they already had. If Notion returns no email for anyone, the sync stops and asks you to enable the email capability.
- **Personal access tokens** from Developer tools are not a supported auth method.

## Troubleshooting

<AccordionGroup>

<Accordion title="Troubleshooting" icon="circle-exclamation">

### Common issues

**Redirect URI mismatch**

- The value in Notion must **exactly** match the Redirect URL shown in PipesHub (scheme, host, path, no stray spaces).
- Team and Personal use different paths (`/Notion` vs `/Notion%20Personal`). Register the URI for the connector you are setting up.

**Invalid client / secret**

- Regenerate the secret in Notion if needed and paste the new value into **Authenticate Instance**.

**Sync failed with a token or capability message**

| Message | What to do |
|---------|------------|
| *Notion rejected the API token: it is invalid or was revoked.* | Copy a current **Access token** from the connection and paste it on **Authenticate Instance**. |
| *The Notion integration is missing the … capability.* | Enable the named capability (**Read content**, **Read comments**, or **Read user information including email addresses**) on the connection, then sync again. |
| *Notion token is missing the … capability* or *Notion OAuth token is no longer active* | Enable the capability on the connection, then use **Re-authenticate with provider** on **Authorize**. |
| *Notion returned no email address for any workspace member.* | Enable **Read user information including email addresses** on the connection, then sync again. |

PipesHub also sends a notification when a sync fails, and a warning when some pages could not be read. Those pages are retried on the next sync.

**Internal secret rejected**

- Use an **internal connection** installation token (`ntn_...`), not a Notion personal access token.

**Missing pages after sync**

- Re-run **Authorize** and add the pages, or share them with an internal connection (**Content access** or **Add connection**). The connector only sees content you explicitly share.
- Pages you share later are picked up at the end of the next sync. If they are still missing after a sync finishes, check the instance for a sync warning. See [Current limitations](#current-limitations).

**Everyone can see a private page (team)**

- Expected for the team connector. It does not apply Notion page ACLs. Remove the page from the integration, or use **Notion Personal**.

**Email / visibility**

- Confirm **Capabilities** include **user information with email**, and that people sign in to PipesHub with the same address as in Notion.
- On Notion Personal, only the PipesHub user who created the instance can search its records. Other users will not see them.

**Reindex does nothing / manual indexing stuck**

- Reindex is supported for pages, databases, and file attachments. After you change **Index Pages**, **Index Databases**, or **Index Files**, reindex the affected records so the new toggles apply.

**Sync is slow or hits Notion limits**

- Notion allows about **3 requests per second** per integration. Large pages (many blocks) need many API calls. The first sync of a big workspace can take a long time; later incremental runs only fetch changes.

## Data sync behavior

<AccordionGroup>

<Accordion title="Synchronization process" icon="sync">

### Initial sync

- Imports pages and databases in the granted scope, plus comments and file attachments when those capabilities and indexing toggles are on.
- Duration depends on workspace size and Notion's rate limit.

### Incremental sync

- Runs on your **Sync interval** when using a scheduled strategy. It fetches pages and databases with a newer **`last_edited_time`** than the last successful run.
- At the end of each sync, newly shared pages are added and deleted, trashed, or unshared pages are removed.
- Comment changes and moves without an edit can lag. See [Current limitations](#current-limitations).
- Not realtime. Use manual **Sync** or **Full sync** when you need an immediate refresh.

### Reindex

- Re-fetches selected pages, databases (data sources), and file attachments and republishes them for indexing.

</Accordion>

## FAQ

<AccordionGroup>

<Accordion title="Queries not returning results. What could be wrong?">

1. **Wrong connector** - Team records are visible to mapped workspace members. Personal records are visible only to the creator.
2. **Email mismatch** - On the team connector, use the same email in PipesHub as in Notion.
3. **Scope** - Confirm the right pages were selected during **Authorize** (or shared with the internal connection) and that indexing toggles match what you expect.
4. **Still indexing** - Open the instance **Overview** until queues complete.

</Accordion>

<Accordion title="Should I use Notion or Notion Personal?">

Use **Notion Personal** for your own notes, private pages, or any content that should not be searchable by the rest of the workspace.

Use the **team** connector when the workspace should share one searchable knowledge set - and only after you accept that **every mapped Notion member can search every page this instance syncs**.

</Accordion>

<Accordion title="Does the team connector honor Notion page permissions?">

No. Notion's API does not expose who a page is shared with, so PipesHub cannot copy those ACLs. The team connector grants read access on the whole synced set to workspace members it can identify by email.

</Accordion>
