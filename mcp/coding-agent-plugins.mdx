One package, `@pipeshub-ai/mcp`, backs three thin plugins. Each adds the PipesHub MCP server and the PipesHub skill to your coding agent, so it can search and cite your team's documents, tickets and chat, and, once you index it, the code of the repository you work in.

| | Claude Code | Codex CLI | Cursor |
| --- | --- | --- | --- |
| Install | `claude plugin marketplace add pipeshub-ai/mcp-server`, then `claude plugin install pipeshub@pipeshub` | `codex plugin marketplace add pipeshub-ai/mcp-server`, then `codex plugin add pipeshub@pipeshub` | A team admin imports the repository as a team marketplace; see [Cursor](/mcp/cursor#plugin) |
| PipesHub Cloud or your own server | `/pipeshub:setup cloud` (a personal access token in `PIPESHUB_MCP_TOKEN`) | `pipeshub login`, then `pipeshub mcp install --client codex` | `setup` command (`pipeshub login`) |
| PipesHub on this computer | `/pipeshub:setup local` | `pipeshub init --local --client codex` | `pipeshub init --local --client cursor` |
| Index this repository | `/pipeshub:index` | ask Codex to index the repository, or run `pipeshub index` | `index` command, or `pipeshub index` |

## PipesHub on this computer

`pipeshub init --local` starts PipesHub with Docker (or uses the one already running), signs the CLI in on this computer, adds a `pipeshub` MCP server and a short instruction file to each coding agent it finds, and indexes the git repository you run it in. It needs Docker and Node.js 20 or later.

```bash
npx @pipeshub-ai/standalone init --local                 # every agent it finds
npx @pipeshub-ai/standalone init --local --client codex  # only Codex
```

The sign-in stays in the CLI's own credential file (`~/.config/pipeshub/credentials.json`, mode 0600). No token is written into an agent's config. `pipeshub uninstall` removes what `init --local` added.

## Index this repository

```bash
pipeshub index          # or: npx @pipeshub-ai/standalone index
pipeshub index --watch  # keep the index current while you work
```

`index` sends the repository's tracked and untracked files to the PipesHub the CLI is signed in to. It respects `.gitignore`, skips binary and very large files, and never sends files that usually hold secrets, such as `.env` files and private keys. It prints progress and waits until the repository is indexed. After that the agent's `pipeshub_code_*` tools answer where something is defined, what calls it and what a change would affect, and cite file paths and line ranges.

Pushing a repository needs the `code:write` scope on the sign-in or token the CLI uses. See [OAuth 2.0](/developer/oauth2).

## Claude Code

The plugin adds the MCP server, the PipesHub skill, and three commands:

- `/pipeshub:setup [cloud|local]` checks the Cloud connection, or sets up PipesHub on this computer.
- `/pipeshub:index [path]` indexes the current repository.
- `/pipeshub:ask <question>` answers from PipesHub, with citations.

In Cloud mode the plugin reads `PIPESHUB_MCP_TOKEN` and, for your own server, `PIPESHUB_MCP_URL` from your shell; see [Claude Code](/mcp/claude-code#plugin). In local mode, `/pipeshub:setup local` adds a separate `pipeshub` server to Claude Code. The plugin's Cloud server then shows as failed without a token; turn it off in `/mcp`.

If the local runtime is not installed, `/pipeshub:setup local` and `/pipeshub:index` say so and print the command that installs it.

## Codex CLI

Codex installs the plugin from the repository's marketplace file. It adds the PipesHub skill and a `pipeshub` MCP server at `http://localhost:3000/mcp`, the address of PipesHub on this computer.

For PipesHub Cloud or your company's server, run `pipeshub mcp install --client codex` (see [Codex CLI](/mcp/codex)). The `pipeshub` entry it writes to `~/.codex/config.toml` takes the place of the plugin's. `pipeshub init --local --client codex` writes the same kind of entry for the local PipesHub, and also adds a PipesHub section to `~/.codex/AGENTS.md`.

## Cursor

The plugin adds the MCP server (which uses the `pipeshub login` sign-in), the PipesHub documentation search server, the skill, and the `setup`, `ask` and `index` commands. See [Cursor](/mcp/cursor#plugin) for the install. With `pipeshub init --local --client cursor --project`, `init` also writes a `.cursor/rules/pipeshub.mdc` rule into the repository.
