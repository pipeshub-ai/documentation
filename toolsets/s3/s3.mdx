## Overview

The Amazon S3 toolset lets PipesHub agents act in Amazon S3 rather than only read from it. It exposes **8 tools**.

If you want Amazon S3 content to be searchable instead, you need a [connector](/connectors/overview). Connectors index data; toolsets perform actions. Many teams use both.

## Setting it up

Toolsets authorise separately from connectors, even where you already have a connector for the same service. A connector indexes data for search; a toolset lets an agent act.

1. Create an API credential in the provider's own console, scoped to the least access the agent needs.
2. In PipesHub, go to **Workspace settings → Connectors → Your Connectors** and find this integration.
3. Select **Setup**, paste the credential, and save.

<Note>
An agent can do anything the credential allows. Prefer a dedicated, least-privilege credential over reusing an administrator's.
</Note>

## Available Tools

| Tool | What it does |
|------|--------------|
| `s3.copy_object` | Copy an object in S3 |
| `s3.create_bucket` | Create a new S3 bucket |
| `s3.delete_bucket` | Delete an S3 bucket |
| `s3.delete_object` | Delete an object from S3 |
| `s3.get_object` | Get an object from S3 |
| `s3.list_buckets` | List all S3 buckets |
| `s3.list_objects` | List objects in an S3 bucket |
| `s3.put_object` | Upload an object to S3 |

## Using it in an agent

1. Open **Agents** and create or edit an agent.
2. From the **Tools** panel, drag this toolset onto the canvas and connect it to the Agent Core.
3. To let the same agent also search indexed content, add a node from the **Knowledge** panel and connect that too.

The agent chooses which tool to call from the descriptions above, so a clear instruction such as "create an issue titled X" routes better than a vague one.
