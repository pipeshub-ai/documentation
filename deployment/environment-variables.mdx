A Docker Compose install reads its settings from `.env` in the install directory (`./pipeshub` by default). The installer writes that file and generates the secrets. The full list with comments is `deployment/docker-compose/env.template` in the [pipeshub-ai repository](https://github.com/pipeshub-ai/pipeshub-ai/blob/main/deployment/docker-compose/env.template).

The **Default** column is the value Docker Compose uses when the variable is not in `.env`. "Empty" means the service's built-in behaviour applies.

## Applying a change

1. Edit `.env` in the install directory.
2. From that directory, recreate the containers:

   ```bash
   docker compose -p pipeshub-ai up -d
   ```

   Use the value of `COMPOSE_PROJECT_NAME` in `.env` if you changed the project name.

`./install.sh --reconfigure` runs the wizard again and rewrites `.env` from scratch. It keeps the existing secrets and saves the old file as `.env.bak.<timestamp>`, but check that any variable you added by hand is still there afterwards.

<Warning>
Do not change `SECRET_KEY` or a database password on an existing install. The databases were created with them, and stored settings are encrypted with `SECRET_KEY`.
</Warning>

## Required

The installer generates all of these. Set them yourself only if you write `.env` by hand.

| Variable | What it does |
|---|---|
| `SECRET_KEY` | Encrypts stored configuration, such as model and connector credentials. The services refuse to start without it. |
| `MONGO_USERNAME`, `MONGO_PASSWORD` | MongoDB root user. Default username `admin`. |
| `NEO4J_PASSWORD` | Neo4j password, when `DATA_STORE=neo4j`. |
| `ARANGO_PASSWORD` | ArangoDB root password, when `DATA_STORE=arangodb`. |
| `QDRANT_API_KEY` | Key shared by Qdrant and the app. |
| `REDIS_PASSWORD` | Redis password. Empty runs Redis without one. |

## Core

| Variable | Default | What it does |
|---|---|---|
| `NODE_ENV` | `production` | Set `production` on any real deployment. `env.template` ships `development`; the installer writes `production`. |
| `LOG_LEVEL` | `info` | Log level for the services. |
| `FRONTEND_PUBLIC_URL` | Empty | Public HTTPS URL people use to open PipesHub. Used for OAuth callbacks and email links. |
| `APP_PORT` | `3000` | Host port Docker publishes. |
| `ALLOWED_ORIGINS` | Empty | Browser origins allowed to call the API, comma-separated. |
| `IMAGE_TAG` | `latest` | Image tag for the app and sandbox images. `env.template` and the `slim` and `eval` installs use `slim`. |
| `COMPOSE_PROJECT_NAME` | `pipeshub-ai` | Docker Compose project. Volume names start with it. The installer writes it; `--stop` and `--uninstall` read it. |
| `COMPOSE_PROFILES` | `graph-neo4j,sandbox` in `env.template` | Which optional containers start. See [Backends](#backends). |
| `TELEMETRY_COLLECTION_FLAG` | Empty (on) | `false` turns off telemetry collection in every service. |
| `LOG_MAX_SIZE`, `LOG_MAX_FILE` | `20m`, `15` | Docker log rotation for the app container. |

## Signing secrets and tokens

| Variable | Default | What it does |
|---|---|---|
| `JWT_SECRET`, `SCOPED_JWT_SECRET`, `COOKIE_SECRET` | Empty | Seed the signing secrets on a fresh install only. Otherwise they are generated on first start and stored; later values are ignored. |
| `ROTATE_SIGNING_SECRETS` | Empty | Written by `./install.sh --rotate-signing-secrets`. See [Rotate signing secrets](/deployment/signing-secrets). |
| `ACCESS_TOKEN_EXPIRY` | `24h` | Lifetime of an access token. |
| `REFRESH_TOKEN_EXPIRY` | `720h` | Lifetime of a refresh token. |
| `PASSWORD_RESET_LINK_EXPIRY` | `20m` | Lifetime of a password-reset link. |
| `MCP_SCOPES` | All scopes, including `code:read` | OAuth scopes for MCP access, comma-separated. If you set it, include `code:read`, or first-run setup stops with "Scopes not allowed for this app: code:read". |
| `PIPESHUB_ENABLE_DCR` | Empty (off) | `true` turns on OAuth dynamic client registration (RFC 7591). |
| `PIPESHUB_ENABLE_DEVICE_GRANT` | Empty (on) | `false` turns off the OAuth device authorization grant (RFC 8628). |
| `HIDE_SECRET_CONFIG` | `false` | `true` masks secrets, including sign-in and OAuth app secrets, in settings responses until revealed. |

## Rate limits and proxies

See [Rate limits and API errors](/additional-resources/rate-limits-and-errors) for how each limit counts.

| Variable | Default | What it does |
|---|---|---|
| `MAX_REQUESTS_PER_MINUTE` | `2000` | Requests per minute for each signed-in user (else each IP) across the API. Not in `env.template`. Without Docker Compose the built-in default is `1000`. |
| `MAX_AUTH_REQUESTS_PER_MINUTE` | `10` | Sign-in, OTP and password requests per minute for each account. One IP may send six times this across all accounts. |
| `MAX_OAUTH_CLIENT_REQUESTS_PER_MINUTE` | `1000` | Requests per minute to OAuth app, personal access token, service account and OAuth token routes. Not in `env.template`. |
| `TRUST_PROXY` | Empty | Which reverse proxies to trust for the client IP. Behind one proxy (Nginx, Caddy, Traefik) use `1`, or list the proxy addresses or CIDRs. Never use `true`. |

## Backends

Each backend variable must agree with `COMPOSE_PROFILES`. A backend whose profile is missing is not running, and a profile with no matching backend starts a container nothing uses.

| Variable | Default | Profile | What it does |
|---|---|---|---|
| `DATA_STORE` | `neo4j` | `graph-neo4j` or `graph-arango` | Graph database: `neo4j` or `arangodb`. |
| `KV_STORE_TYPE` | `redis` | `kv-etcd` for `etcd` | Key-value store for configuration: `redis` or `etcd`. |
| `MESSAGE_BROKER` | `redis` | `broker-kafka` for `kafka` | Message broker: `redis` (Redis Streams) or `kafka`. |
| `VECTOR_COLLECTION_STRATEGY` | `single` | — | `single` puts all records in one Qdrant collection; `per_connector_type` uses one per connector type. Do not change it on an existing install: the services stop at startup. |

Other profiles: `sandbox` (coding sandbox; leave it out for `eval`), `search-searxng` (needs `SEARXNG_SECRET`) and `fetch-crawl4ai` (needs `CRAWL4AI_API_TOKEN`). See [Web Search](/web-search).

### Redis Streams

| Variable | Default | What it does |
|---|---|---|
| `REDIS_STREAMS_RETENTION_MODE` | `after_ack` | `after_ack` trims a stream only behind its consumers. `maxlen` caps every stream and drops unconsumed events past the cap. |
| `REDIS_STREAMS_MAXLEN` | `500000` | Cap for streams with no consumer group, or for every stream with `maxlen`. |
| `FAIR_SCHEDULING_LANE_COUNT` | `8` | Indexing lanes. Every service must use the same count. |
| `FAIR_SCHEDULING_LANE_ASSIGNMENT` | `assigned` | `assigned` gives each connector the least busy lane; `hash` picks a lane from the connector id. |
| `MAX_DELIVERY_ATTEMPTS` | `3` | Deliveries before a message is dead-lettered. |

## Memory and databases

| Variable | Default | What it does |
|---|---|---|
| `APP_MEMORY_LIMIT` | `10G` | Memory cap for the app container. The installer sets it from the machine's memory less 4 GB, between 6 GB and 32 GB. Indexing and parsing concurrency is sized from it, so it is the main throughput setting. |
| `APP_MEMSWAP_LIMIT` | `16G` | Memory plus swap cap for the app container. Keep it at or above `APP_MEMORY_LIMIT`. |
| `QDRANT_MEMORY_LIMIT` | `6G` | Memory cap for Qdrant. Search slows when the index outgrows it. |
| `MONGO_CACHE_GB` | `1` | MongoDB WiredTiger cache. |
| `MONGO_MEMORY_LIMIT` | `2G` | Memory cap for MongoDB. Raise it together with `MONGO_CACHE_GB`. |
| `MONGO_GLIBC_TUNABLES` | `glibc.pthread.rseq=0` | Set `glibc.pthread.rseq=1` if MongoDB keeps exiting with code 139. |
| `MONGO_IMAGE_TAG` | `8.0.17` | MongoDB image. MongoDB 8 data cannot be read by 7, so do not downgrade an existing volume. |

## Indexing and parsing

Leave these unset unless you are tuning a known bottleneck. Empty values let the services size themselves from the CPU and memory limits.

| Variable | Default | What it does |
|---|---|---|
| `MAX_CONCURRENT_PARSING`, `MAX_CONCURRENT_INDEXING`, `MAX_PENDING_INDEXING_TASKS` | Empty | Caps on parsing and indexing concurrency. Set a number only to cap. |
| `INDEXING_UVICORN_WORKERS`, `PARSING_UVICORN_WORKERS`, `DOCLING_UVICORN_WORKERS` | `1` | Worker processes for those services. |
| `QUERY_UVICORN_WORKERS` | Empty | Worker processes for the query service. |
| `CONNECTOR_UVICORN_WORKERS` | `1` | Worker processes for the connector service. Raising it can run duplicate syncs at once. |
| `UVICORN_WORKER_HEALTHCHECK_TIMEOUT_SECONDS` | `60` | Seconds a worker may stop answering before it is replaced. |
| `LOCAL_DOCLING_PARSE_WORKERS`, `PDF_OCR_DETECTION_WORKERS` | `1` | Local Docling and OCR-detection workers. |
| `ENABLE_PDFPLUMBER_PROCESSOR` | `false` | Read text PDFs with the local PdfPlumber parser. |
| `PDF_DOCLING_MAX_PAGES` | `30` | Text PDFs longer than this go to PdfPlumber; `0` sends every text PDF there. |
| `PARSE_POOL_WORKERS` | Empty | Processes that parse large text, code and CSV files. Empty derives it from the CPU limit; `0` uses threads. |
| `CODE_FILE_MAX_SIZE_MB` | Empty (5) | Largest code-repository file read as code or text. |
| `CONNECTOR_SYNC_MAX_CONCURRENT` | `8` | Most connector syncs running at once. |
| `CONNECTOR_SYNC_DELETE_STOP_WAIT_SEC` | `15` | How long a connector delete waits for its running sync to stop. |
| `MAX_TABLE_ROWS_FOR_LLM` | `1000` | Table-row threshold for processing with the language model. |
| `EXCEL_MAX_TABLE_ROWS_TO_INDEX` | `20000` | Most rows indexed from one Excel table. |
| `EXCEL_HEADER_GENERATION_SAMPLE_SCAN_LIMIT` | `500` | Rows scanned to generate Excel table headers. |
| `EMBEDDING_SERVER_MAX_CONCURRENCY`, `EMBEDDING_BATCH_CONCURRENCY` | Empty | Caps on the bundled embedding server. |
| `EMBEDDING_SERVER_QUERY_RESERVED_SLOTS` | Empty (1) | Embedding slots kept for search queries. |
| `EMBEDDING_SERVER_MODEL_IDLE_SECONDS` | Empty (900) | Seconds before an unused local embedding model is unloaded; `0` keeps it loaded. |
| `PARSE_MAX_ORG_SHARE` | Empty (0.5) | Share of a parse pool one organization may hold while another waits. |

`env.template` also lists `GOVERNOR_*` and `INDEXING_SPLIT_LEASE_POOLS` resource-governor settings. Leave them empty.

## Search and answers

| Variable | Default | What it does |
|---|---|---|
| `TARGETED_RETRIEVAL` | Empty (on) | Agents read only the relevant part of a record. `false` turns it off. On by default since 1.0. |
| `TIMELINE_SUMMARIES` | Empty (on) | Timeline search over date ranges. `false` turns it off. On by default since 1.0. |
| `HIGH_ACCURACY_MODE` | `false` | `true` turns on features that spend more compute per question, and named-entity extraction while indexing. |
| `PIPESHUB_AGENT_MAX_TURN_OUTPUT_CHARS` | Empty (1000000) | Most characters one agent turn may stream before it is stopped. `0` removes the limit. |
| `PIPESHUB_ACCESSIBLE_RECORDS_CACHE`, `PIPESHUB_ACCESSIBLE_RECORDS_CACHE_TTL` | Empty (on), `300` | Cache of the records a user can access, and its lifetime in seconds. |

## Code graph

| Variable | Default | What it does |
|---|---|---|
| `CODE_GRAPH_ENABLED` | `true` | `false` indexes code for search only, with no code graph. |
| `CODE_GRAPH_BACKFILL` | `false` | `true` re-indexes, on the next start, repositories indexed before the current code-graph version. |
| `CODE_FILE_CLASSIFICATION` | `true` | Per-file classification of code with the language model. |
| `CODE_EDGE_BUILD_RECONCILE_INTERVAL_SECONDS` | Empty (600) | How often the connector service looks for repositories that still need a graph build. |
| `CODE_EDGE_FULL_REBUILD_INTERVAL_SECONDS` | Empty (604800) | Full rebuild of each repository's graph, in seconds (7 days). |
| `CODE_EDGE_BUILD_MAX_CONCURRENT`, `CODE_EDGE_BUILD_MAX_PER_ORG` | Empty (2, 1) | Graph builds at once per connector process, and per organization. |
| `CODE_EDGE_BUILD_MAX_BLOCKS` | Empty (300000) | Largest repository one build loads. |
| `CODE_EDGE_BUILD_MAX_FAILURES` | Empty (6) | Failed attempts before a build is marked failed. |

## Network and security

| Variable | Default | What it does |
|---|---|---|
| `PIPESHUB_BLOCK_PRIVATE_ADDRESSES` | Empty | `true` refuses AI model endpoints and connector servers on private or internal addresses. Use it when organizations that do not trust each other share one deployment. |
| `WEB_CONNECTOR_ALLOWED_HOSTS` | Empty | Internal host names the Web and RSS connectors may crawl, comma-separated. |
| `CONNECTOR_EGRESS_IPS` | Empty | Public IPs shown in connector forms for firewall allow-lists. Empty looks them up once; `none` hides them. |
| `PIPESHUB_NEXTCLOUD_ALLOW_INSECURE_HTTP` | Empty | `true` lets the Nextcloud connector use an `http://` URL. |
| `MCP_ALLOW_CUSTOM_STDIO` | `false` | `true` allows custom STDIO MCP servers, which run an admin-entered command inside the app container. |
| `SANDBOX_ALLOW_NETWORK` | `false` | `true` gives agent-generated code network access. Private and cloud-metadata addresses stay blocked. |
| `SANDBOX_EGRESS_ALLOW_CIDRS` | Empty | Private ranges sandboxed code may still reach, such as a package mirror. |
| `WEB_FETCH_RENDER_JS` | Empty | `off` stops chat from rendering pages in the headless browser. |
| `SEARXNG_SECRET` | Empty | Required with the `search-searxng` profile. |
| `CRAWL4AI_API_TOKEN` | Empty | Required with the `fetch-crawl4ai` profile. |

## Air-gapped hosts

| Variable | Default | What it does |
|---|---|---|
| `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE` | Empty | Set both to `1` on a host with no internet that already has the models, such as the `latest` image. Leave them empty on `slim`, which downloads the embedding model on first use. |

See [Private Cloud & On-Premises](/deployment/vendor/private).

## Installer variables

These are read by `install.sh` itself, for scripted installs. They are not written to `.env` unless noted.

| Variable | What it does |
|---|---|
| `PIPESHUB_DEPLOY_TYPE` | `slim`, `full` or `eval`. See [System Requirements](/deployment/system-requirements#deployment-types). |
| `PIPESHUB_GRAPH_DB`, `PIPESHUB_BROKER`, `PIPESHUB_KV_STORE` | `neo4j` or `arango`; `redis` or `kafka`; `redis` or `etcd`. |
| `PIPESHUB_VERSION` | Image tag, same as `--version`. |
| `PIPESHUB_NO_PULL` | `1` or `true`, same as `--no-pull`. |
| `PIPESHUB_PORT` | Host port. Default `3000`. |
| `PIPESHUB_PROJECT` | Compose project name. Default `pipeshub-ai`. Use it to run a second copy. |
| `PIPESHUB_PUBLIC_URL` | Public HTTPS URL, written as `FRONTEND_PUBLIC_URL`. |
| `PIPESHUB_IMAGE_SOURCE` | `prebuilt` (default) or `local` to build from a clone. |
| `PIPESHUB_IMAGE` | App image repository. Default `pipeshubai/pipeshub-ai`. Saved in `.env`. |
| `PIPESHUB_COMPOSE_OVERRIDES` | Extra Compose files layered over `docker-compose.yml`, colon-separated. Saved in `.env`. |
| `PIPESHUB_ENV_EXTRA` | A file whose lines are added to a newly written `.env`. |
| `HEALTH_WAIT_SECS` | How long the installer waits for the health check. Default `420`. |
