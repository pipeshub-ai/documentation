## Presentation tier

### Web app in browser

[Next.js](https://nextjs.org/). Search, chat, and admin. It talks to the API over HTTP and SSE. Express does not serve this app.

### MCP clients and agents

The API exposes MCP at `/mcp` (Streamable HTTP). Same access checks as a signed-in user. Setup: [MCP overview](/mcp/overview).

## Application tier

### Node.js API

Express on the same host as the UI in a typical Compose install. Accounts, permissions, knowledge bases, files, OAuth, personal access tokens, and **`/mcp`**. Operator pages: [user management](/system-overview/user-management), [knowledge base](/system-overview/knowledge-base), [enterprise search](/system-overview/enterprise-search).

### API modules

Storage, mail, notifications, configuration, auth, and crawl scheduling run **in this process**. They are not separate microservices.

- [Authentication](/system-overview/authentication)
- [Storage](/system-overview/storage)
- [Configuration](/system-overview/configuration-manager)
- [Mail](/system-overview/mail-service)
- [Crawling](/system-overview/crawling-manager)
- [Connector manager](/system-overview/connector-manager) (OAuth tokens and connector config in Node; the Python connectors service does the sync)

### Event bus

Connectors publish records; indexing consumes them.

- On a local machine: **Redis Streams** (`MESSAGE_BROKER=redis`). No Kafka containers.
- In a larger deployment: **Kafka** (`MESSAGE_BROKER=kafka`).

### Query

Python FastAPI. Retrieval and the cited answer. Reads the graph and the vector store, then calls the LLM you configured.

### Indexing

Python FastAPI. Parse, chunk, embed; write vectors and graph nodes. **Docling** handles heavier PDF, table, and OCR parsing. **Parsing** and **Extraction** are optional — start them only with `USE_PARSING_SERVICE=true`.

### Connectors

Python FastAPI. OAuth, token refresh, and sync from Slack, Drive, Jira, Confluence, and the other sources into the graph.

### Embedding

Local dense embeddings (OpenAI-compatible `/v1/embeddings`). Indexing and Query call it over HTTP; it is not on the event bus. Cloud embedding providers do not need this process.

## Data tier

- **Vector DB** — Qdrant by default (`VECTOR_DB_TYPE=qdrant`).
- **Graph DB** — Neo4j by default (`DATA_STORE=neo4j`). ArangoDB is the other option. Same features either way; services go through the graph abstraction, not a vendor driver.
- **Documents** — MongoDB (sessions, file metadata, application state).
- **Files** — local disk, S3, Azure Blob, or GCS. See [storage](/system-overview/storage).
- **Redis** — cache; default store for encrypted config; Redis Streams when that is the broker.
- **etcd** — the other key-value option (`KV_STORE_TYPE=etcd` / the `kv-etcd` Compose profile). A default laptop install does not start etcd.

Datastore notes and vendor links: [external services](/system-overview/external-services).

## Models

You bring the models. An **embedding model** turns parsed text into vectors. An **LLM** writes the cited answer. Any provider, or local (Ollama). The local embedding server is the default for vectors.

## External systems

Identity (Azure AD, Okta, and others), SMTP, and 50+ connectors (SharePoint, Outlook, Slack, Jira, Confluence, Drive, and the rest). Connector list: [connectors overview](/connectors/overview).
