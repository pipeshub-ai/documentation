The S3 connector brings the files and folders in your Amazon S3 buckets into PipesHub, so you can search them and ask questions about them.

<Warning>
  PipesHub does not copy S3 permissions. With a **team** connector, everyone in your organization can search every file it syncs. If you leave **Bucket Names** empty, that is every bucket the key can list. To keep the files to yourself, set it up as a **personal** connector instead.
</Warning>

## Before you start

- An AWS account with the buckets you want to sync.
- Permission in AWS to create an IAM user and access keys (IAM is AWS's tool for users and permissions).
- PipesHub admin rights for a team connector. Anyone can add a personal connector.

## Step 1: Create a read-only access key in AWS

PipesHub only lists and reads your files. It never changes or deletes anything in S3, so give it a read-only key.

<Steps>
  <Step title="Open IAM">
    Sign in to the [AWS console](https://console.aws.amazon.com), search for **IAM** in the top bar and open it.

    <img src="/images/connectors/s3/iam_console.png" alt="Searching for IAM in the AWS console" style={{ display: 'block', margin: '0 auto' }} width="90%" />
  </Step>
  <Step title="Create a user">
    Click **Users** in the left menu, then **Create user**.

    <img src="/images/connectors/s3/create_user.png" alt="The Users page in IAM with the Create user button" style={{ display: 'block', margin: '0 auto' }} width="90%" />

    Enter a name such as `PipesHub-S3-Connector` and click **Next**.

    <img src="/images/connectors/s3/user_name.png" alt="Entering the user name" style={{ display: 'block', margin: '0 auto' }} width="90%" />
  </Step>
  <Step title="Give the user read-only access">
    Choose **Attach policies directly**, then pick one:

    - **AmazonS3ReadOnlyAccess**: lets PipesHub read every bucket in the account. Quickest to set up.
    - **Your own policy** for only the buckets you want to sync. See [Read-only policy for chosen buckets](#read-only-policy-for-chosen-buckets) below.

    <img src="/images/connectors/s3/attach_policy.png" alt="Attaching the AmazonS3ReadOnlyAccess policy" style={{ display: 'block', margin: '0 auto' }} width="90%" />

    Click **Next**, then **Create user**.
  </Step>
  <Step title="Create the access key">
    Open the new user, go to the **Security credentials** tab and scroll to **Access keys**.

    <img src="/images/connectors/s3/security_credentials.png" alt="The Security credentials tab of the IAM user" style={{ display: 'block', margin: '0 auto' }} width="90%" />

    Click **Create access key**, choose **Application running outside AWS**, tick the confirmation box and click **Next**.

    <img src="/images/connectors/s3/create_access_key.png" alt="Choosing Application running outside AWS" style={{ display: 'block', margin: '0 auto' }} width="90%" />
  </Step>
  <Step title="Copy the Access Key ID and Secret Access Key">
    Copy both values, or click **Download .csv file**, then click **Done**.

    <img src="/images/connectors/s3/access_key_credentials.png" alt="The new access key and secret access key" style={{ display: 'block', margin: '0 auto' }} width="90%" />

    <Warning>
      AWS shows the Secret Access Key only once. If you lose it, create a new key.
    </Warning>
  </Step>
</Steps>

### Read-only policy for chosen buckets

To limit PipesHub to some buckets, create a policy in IAM (**Policies** → **Create policy** → **JSON**), paste this, replace `your-bucket-1` and `your-bucket-2` with your bucket names, and attach it to the user instead of **AmazonS3ReadOnlyAccess**.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListBuckets",
      "Effect": "Allow",
      "Action": ["s3:ListBucket", "s3:GetBucketLocation"],
      "Resource": ["arn:aws:s3:::your-bucket-1", "arn:aws:s3:::your-bucket-2"]
    },
    {
      "Sid": "ReadFiles",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": ["arn:aws:s3:::your-bucket-1/*", "arn:aws:s3:::your-bucket-2/*"]
    },
    {
      "Sid": "ShowBucketList",
      "Effect": "Allow",
      "Action": "s3:ListAllMyBuckets",
      "Resource": "*"
    }
  ]
}
```

<Info>
  **When `s3:ListAllMyBuckets` is needed.** PipesHub uses it to show your buckets in the **Bucket Names** list, so keep it while you set up the connector or change that filter. It is also needed for every sync if **Bucket Names** is empty (PipesHub then finds all your buckets itself) or set to **Not in**. Once you have saved bucket names with **In**, syncs read those buckets directly, and you can remove this permission. Add it back before you edit the bucket list.
</Info>

If a bucket is encrypted with your own AWS KMS key (SSE-KMS), also allow `kms:Decrypt` on that key.

## Step 2: Connect S3 in PipesHub

<Steps>
  <Step title="Find S3">
    In PipesHub, go to **Workspace** → **Connectors**, search for **S3** and click **Set up** on the S3 card. For a personal connector, use **Your connectors** at the top right instead.

    <img src="/images/connectors/s3/pipeshub-find.png" alt="The Connectors page with S3 found by search" style={{ display: 'block', margin: '0 auto' }} width="95%" />
  </Step>
  <Step title="Confirm a team connector">
    PipesHub warns that everyone in your organization will see the synced data. Click **Continue with team connector**, or **Set up personal connector** to keep the files to yourself.

    <img src="/images/connectors/s3/pipeshub-team-warning.png" alt="Dialog: Everyone in your organization will see this data" style={{ display: 'block', margin: '0 auto' }} width="65%" />
  </Step>
  <Step title="Fill in the Authenticate tab">
    - **Instance name**: any label, for example `S3` or `Marketing files`.
    - **Authentication method**: leave it on **Access key**. You can't change this after you create the connector.
    - **Access Key**: the Access Key ID from Step 1.
    - **Secret Key**: the Secret Access Key from Step 1.

    Paste the keys without extra spaces, then click **Next**.

    <img src="/images/connectors/s3/pipeshub-authenticate.png" alt="The Authenticate tab with Instance name, Authentication method and the Access Key and Secret Key fields" style={{ display: 'block', margin: '0 auto' }} width="60%" />

    <Accordion title="Use an IAM role instead (AssumeRole)">
      Choose this if your company prefers PipesHub to borrow a role's permissions for a short time instead of using a key with S3 access, for example to read buckets in another AWS account. Set **Authentication method** to **IAM Role (AssumeRole)** and fill in:

      - **Access Key** and **Secret Key**: a key whose only permission is `sts:AssumeRole` on the role. Give it no S3 access.
      - **Role ARN**: the role PipesHub should use, for example `arn:aws:iam::123456789012:role/pipeshub-s3-reader`. Give this role the read-only S3 permissions from Step 1.
      - **External ID** (optional): only if the role's trust policy requires one.

      The role's trust policy must allow the key's IAM user to assume it. AWS explains this in [Access for third parties](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_common-scenarios_third-party.html). PipesHub renews the role's short-lived credentials by itself.

      <img src="/images/connectors/s3/pipeshub-authenticate-assume-role.png" alt="The Authenticate tab with IAM Role (AssumeRole) selected, showing Access Key, Secret Key, Role ARN and External ID" style={{ display: 'block', margin: '0 auto' }} width="60%" />
    </Accordion>
  </Step>
  <Step title="Set up the Configure records tab">
    Pick a **Sync strategy** and **Sync interval**, and add any filters you need. See [Choose what to sync](#choose-what-to-sync). With no filters, PipesHub syncs every bucket the key can list.

    <img src="/images/connectors/s3/pipeshub-configure.png" alt="The Configure records tab with Sync settings, Enable Manual Indexing and Sync filters" style={{ display: 'block', margin: '0 auto' }} width="60%" />
  </Step>
  <Step title="Save and start syncing">
    Click **Save configuration**, then **Start syncing now**. If you choose **I'll do it later**, turn on **Sync enabled** on the connector's card when you are ready.

    <img src="/images/connectors/s3/pipeshub-ready.png" alt="Dialog: Instance is configured and ready to sync, with Start syncing now" style={{ display: 'block', margin: '0 auto' }} width="55%" />

    Before the first sync, PipesHub checks that the key can read the buckets you chose. If it can't read any of them, sync stays off and the message names the missing permission. If it can read only some, the readable ones sync and you get a warning naming the rest.
  </Step>
</Steps>

<Tip>
  To sync another AWS account, set up a second S3 connector with that account's key.
</Tip>

## Choose what to sync

These settings are on the **Configure records** tab. You can change them later; changes apply from the next sync.

| Setting | What it does |
|---------|--------------|
| **Sync strategy** | **Scheduled** checks S3 for changes automatically. **Manual** syncs only when you click **Sync**. |
| **Sync interval** | How often a scheduled sync runs. The default is every hour. |
| **Enable Manual Indexing** | Off: every synced file becomes searchable. On: files are synced but only become searchable after you choose them. Leave it off unless you want to pick files one by one. |
| **Folders** filter | Folder paths inside each bucket, such as `reports/2026`. Press Enter after each one. **In** syncs only those folders and their subfolders; **Not in** syncs everything except them. |
| **Bucket Names** filter | Pick buckets from the list (search matches the start of the name). **In** syncs only those buckets; **Not in** syncs every bucket except them. Leave it out to sync every bucket the key can list. |
| **File Extensions** filter | Sync only certain file types, or leave some out, for example `pdf, docx, txt`. |
| **Modified Date** filter | Sync only files last changed before, after or between the dates you choose. S3 doesn't record a creation date, so there is no Created Date filter. |

Add the last three with **Add filter**. Filters are the easiest way to make a large first sync faster.

<Note>
  When you narrow a filter, PipesHub removes the files it now leaves out, so they also disappear from search.
</Note>

## What gets synced and how it stays up to date

- **What you see:** each bucket appears in PipesHub with its folders and files. Documents, text and code files, and JPG, PNG, WebP and SVG images become searchable. Videos, audio, GIFs, archives and password-protected files are listed but their content isn't searchable. Images are searchable by their content only if your PipesHub has an AI model that can read images: a multimodal chat or embedding model under **Workspace** → **AI models**.
- **How often:** on the schedule you chose (every hour by default), or when you click **Sync**. The first sync of a large bucket can take hours; later syncs only download files that are new or changed.
- **Edits:** a changed file is downloaded and indexed again on the next sync. A file that is moved or renamed without changes keeps its place in search.
- **Deletes:** a file deleted in S3 is removed from PipesHub after the next sync that finishes without errors. A deleted bucket is removed on the next sync, once S3 reports that it no longer exists.
- **Who can see it:** a team connector makes the files searchable by everyone in your organization. A personal connector keeps them to you. S3 bucket policies and ACLs only limit what the key can read.

**Not synced:**

- The content of files in S3 Glacier Flexible Retrieval or Glacier Deep Archive. Restore them first.
- Files encrypted with your own keys (SSE-C) or encrypted before upload.
- Requester Pays buckets owned by another AWS account.
- Other S3-compatible storage. For MinIO, use the separate MinIO connector.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Sync won't start: the key is rejected">
    The Access Key or Secret Key is wrong, has extra spaces, or was deleted or rotated in AWS. Check the user's **Security credentials** in IAM, create a new key if needed, and update it in the connector's settings.
  </Accordion>
  <Accordion title="Sync won't start: a permission is missing">
    The message names the permission, for example `s3:ListBucket` or `s3:GetObject`. Add it to the user's policy (or the role's, for AssumeRole). `s3:ListBucket` and `s3:GetBucketLocation` go on the bucket (`arn:aws:s3:::bucket-name`), `s3:GetObject` on its files (`arn:aws:s3:::bucket-name/*`).
  </Accordion>
  <Accordion title="The Bucket Names list is empty">
    The list needs `s3:ListAllMyBuckets`. Add it to the IAM user behind your access key, or to the role if you use **IAM Role (AssumeRole)**, then reopen the filter. When you search, type the start of the bucket name.
  </Accordion>
  <Accordion title="Sync fails with “Failed to list buckets”">
    **Bucket Names** is empty or set to **Not in**, so PipesHub has to list all buckets, and the IAM user behind your access key (or the role, with AssumeRole) lacks `s3:ListAllMyBuckets`. Add the permission there, or pick your buckets in **Bucket Names** with **In**.
  </Accordion>
  <Accordion title="A notification says some buckets were skipped">
    The key can see those buckets but not read them. Give it read access, or leave those buckets out with the **Bucket Names** filter. Files already synced from them stay in PipesHub.
  </Accordion>
  <Accordion title="Some files are missing">
    Check that your **Folders**, **File Extensions** and **Modified Date** filters don't leave them out, and that the files aren't in Glacier. For files encrypted with a KMS key, the key also needs `kms:Decrypt`.
  </Accordion>
  <Accordion title="Synced files don't show up in search">
    If **Enable Manual Indexing** is on, files aren't searchable until you choose them. Otherwise wait for indexing to finish; large files take longer. Unsupported file types never become searchable.
  </Accordion>
</AccordionGroup>
