## Plugin

The PipesHub plugin for Cursor adds PipesHub's remote MCP server (at the URL you set, signed in with OAuth; no token goes in Cursor's config), the PipesHub documentation search server, the PipesHub skill, and `setup`, `ask` and `index` commands ([indexing a repository](/mcp/coding-agent-plugins#index-this-repository)). It is not yet listed in Cursor's public marketplace.

1. A Cursor team admin imports the repository as a team marketplace: Dashboard → Plugins & MCPs → Team Marketplaces → Add Marketplace → Import from Repo, with `https://github.com/pipeshub-ai/mcp-server` (the repository root).
2. Each developer installs **PipesHub** from Customize, unless the admin sets it Default On or Required.
3. Set the server's URL, `<pipeshub-instanceurl>/mcp` (for example `https://pipeshub.example.com/mcp`). On a team install the admin sets **PipesHub MCP URL** in the dashboard under Plugins. On an individual install Cursor does not ask, so `pipeshub` shows **Error** at first: open Customize → PipesHub → **Configure**, enter **PipesHub MCP URL**, and click **Save**.
4. Sign in. With the URL set, `pipeshub` shows **Needs authentication**. Click **Authenticate**, approve on the PipesHub consent page, and the tools appear. The `setup` command walks through this. If `pipeshub` then shows **Error · Unauthorized**, open its settings, click **Sign out**, and **Authenticate** again.

<Note>
  Cursor signs in by registering itself with PipesHub (dynamic client registration). PipesHub v1.1.0 and older have it off unless `PIPESHUB_ENABLE_DCR=true` is set; later releases have it on unless `PIPESHUB_ENABLE_DCR=false`. With it off, Authenticate fails with 403 `dynamic client registration is disabled`: use the [OAuth app](#oauth-app) setup below instead.
</Note>

The `index` command uploads with the `pipeshub` CLI, which has its own sign-in: `npx -y -p @pipeshub-ai/mcp pipeshub login`.

To configure Cursor by hand instead, use one of the options below.

## OAuth app

Cursor supports static OAuth for remote MCP servers via the `auth` object in `mcp.json`.

<Note>
  Before you start, create an OAuth app in PipesHub and note your **Client ID** and **Client Secret**. See [MCP Server Overview](/mcp/overview#step-1-create-an-oauth-app).
</Note>

<Tip>
  Coding agents: read [For coding agents](/for-agents) first. If they have no PipesHub yet, start on [PipesHub Cloud](https://app.pipeshub.com/?ref=docs), or self-host with the [Local Docker demo](/for-agents-local-demo) (do not scaffold LangChain). MCP config is not enough — also install the skill into **this** repo (`npx skills add pipeshub-ai/mcp-server`) and append the `AGENTS.md` snippet on that page. Otherwise the next chat still invents RAG.
</Tip>

## Configuration

Open **Cursor Settings > Tools and Integrations > New MCP Server**, or edit your project's `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "pipeshub": {
      "url": "PIPESHUB_INSTANCE_URL/mcp",
      "auth": {
        "CLIENT_ID": "YOUR_CLIENT_ID",
        "CLIENT_SECRET": "YOUR_CLIENT_SECRET",
        "scopes": [
          "openid", "profile", "email", "offline_access",
          "semantic:write", "conversation:chat",
          "agent:read", "agent:execute",
          "kb:read", "kb:write", "kb:upload",
          "connector:read", "config:read",
          "user:read", "team:read", "usergroup:read",
          "code:read"
        ]
      }
    }
  }
}
```

Cursor discovers the authorization and token endpoints from PipesHub's OAuth metadata.

<Note>
  If the `scopes` field is omitted, Cursor requests the `scopes_supported` it discovers from the server's OAuth metadata. To limit access, explicitly list only the scopes you need. You can also control which scopes are exposed server-side. See [Customizing Default Scopes](/mcp/overview#customizing-default-scopes).
</Note>

## Using Environment Variables

Use Cursor's `${env:VAR}` interpolation to keep secrets out of config files:

```json
{
  "mcpServers": {
    "pipeshub": {
      "url": "${env:PIPESHUB_INSTANCE_URL}/mcp",
      "auth": {
        "CLIENT_ID": "${env:PIPESHUB_CLIENT_ID}",
        "CLIENT_SECRET": "${env:PIPESHUB_CLIENT_SECRET}",
        "scopes": [
          "openid", "profile", "email", "offline_access",
          "semantic:write", "conversation:chat",
          "agent:read", "agent:execute",
          "kb:read", "kb:write", "kb:upload",
          "connector:read", "config:read",
          "user:read", "team:read", "usergroup:read",
          "code:read"
        ]
      }
    }
  }
}
```

## Redirect URIs

Cursor's static OAuth uses fixed redirect URIs. Register the one for the way you sign in, or both:

| Where you sign in | Redirect URI |
|---|---|
| Cursor web and Cursor Agents | `https://www.cursor.com/agents/mcp/oauth/callback` |
| Cursor desktop app | `http://localhost:8787/callback` |

Add them as allowed redirect URIs when creating the OAuth app in PipesHub.

## OAuth Login Troubleshooting

If Cursor's internal browser fails to load the OAuth login page, copy the authorization URL from the internal browser and paste it into your normal browser to complete the login flow.
