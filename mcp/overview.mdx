## What is the PipesHub MCP Server?

PipesHub exposes a **remote MCP endpoint** over **Streamable HTTP** at `/mcp`. MCP clients connect to this endpoint directly — no local npm packages or stdio processes needed.

<Tip>
  If you are a coding agent (or setting one up), start at [For coding agents](/for-agents).
</Tip>

This lets AI clients such as **Cursor**, **Claude Code**, **Gemini CLI**, **Claude.ai (Web)**, **LibreChat**, and **Omnigent** search and chat over your organization's indexed documents, look up people and groups, and download files.

## Prerequisites

- A running PipesHub instance: [PipesHub Cloud](https://app.pipeshub.com/?ref=docs) or self-hosted. If they have none yet, start on PipesHub Cloud, or self-host with the [Local Docker demo](/for-agents-local-demo); do not scaffold LangChain.
- Either an OAuth app (see [Step 1](#step-1-create-an-oauth-app) below), **or** a [Personal Access Token](/developer/personal-access-tokens) — see the note below for which one to use

<Note>
  Most **client setup guides below** (Cursor, Gemini CLI, Claude.ai, LibreChat) connect over OAuth — you'll need an OAuth app for those. [Claude Code](/mcp/claude-code) and [Omnigent](/mcp/omnigent) are the exceptions: they attach with an `Authorization` header, so a personal access token is all you need. Claude Code can also use an OAuth app for shared or admin-managed setups.

  For your own tooling, skip OAuth entirely: create a **[Personal Access Token](/developer/personal-access-tokens)** under **Developer Settings > Personal Access Tokens** and use it as a `Bearer` token — either directly against `/mcp`, as `--bearer-auth` with the [Local Server (Stdio)](/mcp/local-server) package, or with any MCP client you configure yourself with a custom `Authorization` header.
</Note>

## Step 1: Create an OAuth App

<Steps>
  <Step title="Open Developer Settings">
    Log in to your PipesHub instance as an admin and navigate to **Settings > Developer Settings > OAuth Apps**.
  </Step>
  <Step title="Create the app">
    Click **Create OAuth App** and fill in the app details:
    - **Name**: e.g., `MCP Integration`
    - **Redirect URIs**: Add the redirect URIs for the clients you plan to use (see the table below).
  </Step>
  <Step title="Save and copy credentials">
    Save the app and copy the **Client ID** and **Client Secret**.
  </Step>
</Steps>

### Redirect URIs

Add all the redirect URIs for the clients you plan to use:

| Client | Redirect URI |
|---|---|
| **Cursor** | `cursor://anysphere.cursor-mcp/oauth/callback` |
| **Claude Code** | `http://localhost:<PORT>/callback` (e.g., `http://localhost:8080/callback`) |
| **Claude.ai (Web)** | `https://claude.ai/api/mcp/auth_callback` |
| **Claude Desktop** (custom connector) | `https://claude.ai/api/mcp/auth_callback` |
| **Gemini CLI** | `http://localhost:7777/oauth/callback` |
| **LibreChat** | `http://localhost:3080/api/mcp/<server-identifier>/oauth/callback` |

<Warning>
  The scopes in [`MCP_SCOPES`](https://github.com/pipeshub-ai/pipeshub-ai/blob/main/backend/env.template#L57) must match the scopes granted to your OAuth app — a mismatch will result in an authorization error.
</Warning>

### Customizing Default Scopes

By default, PipesHub exposes some default scopes in its `/.well-known/oauth-protected-resource/mcp` discovery endpoint. You can customize which scopes are exposed by setting the [`MCP_SCOPES`](https://github.com/pipeshub-ai/pipeshub-ai/blob/main/backend/env.template#L57) environment variable on your PipesHub instance. This is useful for clients like Claude Code that automatically request all exposed scopes.

This is the `MCP_SCOPES` value PipesHub ships (`backend/env.template`). It covers chat, search, the directory, agents and code. It also lets an agent create collections and upload into them (`kb:write`, `kb:upload`), and add a website as a source (`connector:write`, `connector:sync`):

```bash
MCP_SCOPES=openid,profile,email,offline_access,semantic:write,conversation:write,conversation:chat,kb:read,kb:write,kb:upload,team:read,user:read,usergroup:read,config:read,agent:read,agent:execute,connector:read,connector:write,connector:sync,code:read,project:read,project:write,project:delete
```

Leave `kb:write` and `kb:upload` out to stop agents creating collections and uploading, and `connector:write` and `connector:sync` out to stop them adding web sources: tokens without them are not offered those tools. With the connector scopes, a token can also create and configure the user's other connectors and start or stop their syncs, as the user could in the connectors page. Other tools that can act, such as `pipeshub_chat` with an agent whose toolsets take actions, are governed by their own scopes.

An instance that sets `MCP_SCOPES` in its `.env` keeps that list after an upgrade until you edit it. After you add the two scopes and restart, new personal access tokens get them, and the built-in PipesHub agent app (device login) adds them to its allowed scopes on the next discovery request. Tokens already issued keep their scopes: mint a new token, or sign the agent in again. An MCP client that registered itself (Dynamic Client Registration) keeps the scopes it registered with, so remove and re-add the server in that client to give it new ones.

## Placeholders

Replace these placeholders in all client configurations:

| Placeholder | Description | Example |
|---|---|---|
| `PIPESHUB_INSTANCE_URL` | Your PipesHub instance URL | `https://app.pipeshub.com` |
| `YOUR_CLIENT_ID` | OAuth app client ID | `clid_abc123...` |
| `YOUR_CLIENT_SECRET` | OAuth app client secret | `clsec_xyz789...` |
| `YOUR_BEARER_TOKEN` | [Personal access token](/developer/personal-access-tokens) — used by the local stdio bridge and by [Omnigent](/mcp/omnigent) | `phpat_eyJhbGci...` |

The remote MCP endpoint URL is: `PIPESHUB_INSTANCE_URL/mcp`

## How It Works

### Architecture

```
AI Client (Cursor / Claude Code / Gemini CLI / Claude.ai / LibreChat / Omnigent)
        │
        │  HTTP POST (JSON-RPC)
        │  Authorization: Bearer <token>
        ▼
  PIPESHUB_INSTANCE_URL/mcp
        │
        │  StreamableHTTP Transport
        │  (stateless, per-request MCP server)
        ▼
  PipesHub API (curated tool set — see Tools Reference)
```

### OAuth Protected Resource Discovery

PipesHub exposes OAuth protected resource discovery at:

```
PIPESHUB_INSTANCE_URL/.well-known/oauth-protected-resource/mcp
```

This returns all OAuth endpoints automatically:

- Authorization: `PIPESHUB_INSTANCE_URL/api/v1/oauth2/authorize`
- Token: `PIPESHUB_INSTANCE_URL/api/v1/oauth2/token`
- Revocation: `PIPESHUB_INSTANCE_URL/api/v1/oauth2/revoke`
- JWKS: `PIPESHUB_INSTANCE_URL/.well-known/jwks.json`

### Signing in without an OAuth app (Client ID Metadata Documents)

Some MCP clients, such as Claude Code and VS Code, publish their OAuth client details at an `https://` URL and use that URL as their `client_id`. PipesHub supports this ([OAuth Client ID Metadata Documents](https://datatracker.ietf.org/doc/draft-ietf-oauth-client-id-metadata-document/)), and its discovery metadata includes `client_id_metadata_document_supported: true`. With a client like this you skip [Step 1](#step-1-create-an-oauth-app): add the `/mcp` URL to the client and sign in when it opens the browser.

- PipesHub fetches the client's document when you open the sign-in page. It accepts only public clients that use PKCE, and only the redirect URIs that the document lists: `https://`, loopback `http://`, or the client's own app scheme. A loopback redirect URI listed without a port, such as `http://localhost/callback`, matches any port.
- PipesHub stores the client only once you click **Allow**. It re-reads the document on every sign-in, so a client that asks for fewer scopes, or a narrower `MCP_SCOPES`, applies from the next sign-in.
- The consent screen shows the name the client chose, a note that no administrator reviewed it, and **Identified by** with the host of the document URL. Check that host before you click **Allow**.
- These clients get the scopes the MCP tools use, including `offline_access`, so they can refresh their tokens. `MCP_SCOPES` still caps them.
- PipesHub never fetches documents from loopback or private addresses.
- To turn this off, set `PIPESHUB_ENABLE_CIMD=false` on the server. Clients then need an OAuth app or a personal access token.

### Tokens, scopes and limits

- **Which tokens work.** `/mcp` accepts OAuth access tokens and personal access tokens. It refuses the web app's session token.
- **Tokens for `/mcp` only.** A client that sends the `resource` parameter ([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707)) with your instance's `/mcp` URL gets a token marked for `/mcp`, and `/mcp` refuses a token marked for anything else. Clients that send no `resource` keep working as before.
- **Tools follow scopes.** A client sees only the tools its token's scopes cover. If it calls a tool anyway, PipesHub answers `403` with `WWW-Authenticate: Bearer error="insufficient_scope"` and the scopes to ask for, so a client that supports it can ask you for just those.
- **Chat that acts.** `pipeshub_chat` can run your connected actions (create a Jira issue, send a message) only when the token has `agent:execute`. With `conversation:chat` alone it answers without acting.
- **Rate limits.** Each account may make `MAX_REQUESTS_PER_MINUTE` requests a minute to `/mcp` (default 1000); the API calls a tool makes for it are not counted again. Many people behind one address, such as an office or a hosted AI client, do not share one limit. A limit hit is a JSON-RPC error with HTTP `429`.
- **Browser pages.** `/mcp` refuses a request from a web page whose `Origin` is not your instance's (`403`). Desktop, CLI and hosted clients send no `Origin`. To allow a browser-based tool such as an MCP inspector, add its origin to `MCP_ALLOWED_ORIGINS`.
- **Audit trail.** Every tool call is logged with the account, the OAuth app's client ID (`pat-system:` followed by the org ID for a personal access token), the tool, how long it took and whether it failed (`audit: mcp_tool_call` in the Node API's logs). Argument values and results are never logged.
- **Turning an app off.** Suspending or deleting an OAuth app revokes the tokens it issued, so its clients stop at once.

### Request size limit

PipesHub accepts MCP requests of up to 5 MB. A larger request is refused with HTTP 413 and a JSON-RPC error that gives the limit.

Real tool calls are far smaller. A chat question can be at most 100,000 characters, and no tool uploads files. If a client hits the limit, send less in one call, such as a shorter question or fewer IDs.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Incompatible auth server: does not support dynamic client registration">
    This means the client is trying dynamic registration instead of using your pre-configured credentials. Make sure you passed `--client-id` and `--client-secret` (Claude Code) or the `auth` object (Cursor) correctly.
  </Accordion>
  <Accordion title="Authentication fails / redirect error">
    Ensure the **Redirect URI** in your OAuth app matches exactly what the client uses:
    - **Cursor**: `cursor://anysphere.cursor-mcp/oauth/callback`
    - **Claude Code**: `http://localhost:<callbackPort>/callback`
    - **Claude.ai**: `https://claude.ai/api/mcp/auth_callback`
    - **Gemini CLI**: `http://localhost:7777/oauth/callback`
    - **LibreChat**: `http://localhost:3080/api/mcp/<server-identifier>/oauth/callback`

    Also make sure the OAuth app is **active** (not suspended) in PipesHub.
  </Accordion>
  <Accordion title="Cannot reach MCP endpoint">
    - Verify the endpoint is accessible: `curl -X POST PIPESHUB_INSTANCE_URL/mcp` (should return 401, not a connection error).
  </Accordion>
  <Accordion title="Request is too large (HTTP 413)">
    One MCP request can be at most 5 MB. Send less in one call, such as a shorter question or fewer IDs, and try again.
  </Accordion>
  <Accordion title="Debugging with MCP Inspector">
    ```bash
    npx @modelcontextprotocol/inspector
    ```
    Then connect to `PIPESHUB_INSTANCE_URL/mcp` with a Bearer token to test the endpoint directly.
  </Accordion>
</AccordionGroup>

## FAQ

<AccordionGroup>
  <Accordion title="How do I update the scopes for my MCP integration?">
    1. **Update the [`MCP_SCOPES`](https://github.com/pipeshub-ai/pipeshub-ai/blob/main/backend/env.template#L57) environment variable** on your PipesHub instance to include the new scopes you want exposed via the discovery endpoint.
    2. **Update the OAuth app scopes** in PipesHub: go to **Settings > Developer Settings > OAuth Apps**, select your OAuth app, and add or remove scopes as needed.
    3. **Re-authenticate the client** — existing tokens carry the old scopes, so you need to re-authenticate to get a new token with the updated scopes:
       - **Cursor**: Remove and re-add the MCP server, or clear the cached OAuth token and reconnect.
       - **Claude Code**: Run `/mcp` and complete the browser login flow again.
       - **Gemini CLI**: Run `/mcp auth pipeshub` to re-authenticate.
       - **Claude.ai**: Disconnect and reconnect the connector in **Settings > Connectors**.
  </Accordion>
</AccordionGroup>
