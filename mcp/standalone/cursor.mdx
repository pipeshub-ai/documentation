After [`init`](/mcp/standalone/quickstart), Cursor can search your team's documents and, once you have indexed a repository, ask about its code. This page covers what `init` changes for Cursor and how to check it.

## What `init` writes

| File | What |
|---|---|
| `~/.cursor/mcp.json` | The `pipeshub` entry under `mcpServers`, for every project |
| `.cursor/rules/pipeshub.mdc` in your repository | A rule with a description: Cursor attaches it when a request is about the team's knowledge or this code. Only with `init --project` |

Cursor has no user-level instruction file for `init` to write, so run `init --project` in each repository where you want the rule. Cursor has no slash commands from `init`: ask in plain words.

## Check that Cursor sees PipesHub

<Steps>
  <Step title="Restart Cursor">
    Reload the window or restart Cursor.
  </Step>
  <Step title="Open the MCP settings">
    In **Cursor Settings**, open the **Tools & MCP** page (called **MCP** in some versions). `pipeshub` should be listed and enabled with its tools.
  </Step>
  <Step title="Ask in agent mode">
    Ask "Index this repository with PipesHub", then ask who calls a function.
  </Step>
</Steps>

## Without `init`

Start the stack and sign in first ([Set up one agent by hand](/mcp/standalone/quickstart#set-up-one-agent-by-hand)), then add the entry to `~/.cursor/mcp.json` (or `.cursor/mcp.json` in one project):

```json
{
  "mcpServers": {
    "pipeshub": {
      "command": "npx",
      "args": ["-y", "@pipeshub-ai/mcp@>=4.7.0", "start", "--server-url", "http://127.0.0.1:3000"],
      "env": { "PIPESHUB_MCP_CHAT": "off" }
    }
  }
}
```

This is the local setup. To connect Cursor to a hosted PipesHub, see [Cursor](/mcp/cursor).

## Undo

```bash
npx @pipeshub-ai/standalone uninstall --client cursor
```

This removes only what `init` added for Cursor, from the files above. A backup of each file `init` changed is in `~/.config/pipeshub/backups/`. To remove everything, see [Undo everything](/mcp/standalone/quickstart#undo-everything).
