The Nextcloud connector brings the files and folders in your Nextcloud account into PipesHub, so you can search them and ask questions about them. Files other people shared with you in Nextcloud come along too.

<Info>
  Nextcloud is a **personal** connector. Only you, the PipesHub user who sets it up, can search what it syncs. Nobody else in your organization sees your Nextcloud files. Each person who wants their Nextcloud files in PipesHub sets up their own connector.
</Info>

## Before you start

You need:

- A Nextcloud account you can sign in to.
- Your Nextcloud address (for example `https://cloud.example.com`). It must start with `https://`, and the PipesHub server must be able to reach it.
- About five minutes to create an **app password** in Nextcloud. An app password is a separate password just for PipesHub, which you can revoke at any time without changing your normal Nextcloud password.
- Ideally, the Nextcloud **Activity** app turned on (it is on by default). PipesHub uses it to pick up your changes quickly. Without it, syncing still works but is slower.

## Step 1: Create an app password in Nextcloud

<Steps>
  <Step title="Open your personal settings">
    Sign in to Nextcloud, click your profile picture in the top-right corner, and choose **Personal settings**.

    <img src="/images/connectors/nextcloud/n1.png" alt="Nextcloud profile menu with Personal settings" style={{ display: 'block', margin: '0 auto' }} width="90%" />
  </Step>
  <Step title="Create the app password">
    In the left sidebar, click **Security** and scroll down to **Devices & sessions**. In **App name**, type a name you'll recognize, such as `PipesHub`, and click **Create new app password**.

    <img src="/images/connectors/nextcloud/n2.png" alt="Devices & sessions section with the App name field and the Create new app password button" style={{ display: 'block', margin: '0 auto' }} width="90%" />
  </Step>
  <Step title="Confirm with your Nextcloud password">
    If Nextcloud asks, enter your normal Nextcloud password and click **Confirm**.

    <img src="/images/connectors/nextcloud/n3.png" alt="Authentication required dialog asking for your Nextcloud password" style={{ display: 'block', margin: '0 auto' }} width="90%" />
  </Step>
  <Step title="Copy the new app password">
    Nextcloud shows the new app password. Copy it now: Nextcloud shows it only once. Also note the **Login** shown above it; that is your username.

    <img src="/images/connectors/nextcloud/n4.png" alt="New app password dialog with Login and Password and a copy button" style={{ display: 'block', margin: '0 auto' }} width="90%" />
  </Step>
  <Step title="Leave filesystem access on">
    In the **Devices & sessions** list, the new app password's **...** menu has an **Allow filesystem access** option. It is on by default. Leave it on: without it, PipesHub can sign in but can't see any files, and the connector won't turn on.
  </Step>
</Steps>

<Warning>
  Use the app password, never your normal Nextcloud login password.
</Warning>

## Step 2: Connect Nextcloud in PipesHub

<Steps>
  <Step title="Find Nextcloud in your connectors">
    In PipesHub, go to **Personal → Your connectors**, search for **Nextcloud**, and click **Set up** on the Nextcloud card.

    <img src="/images/connectors/nextcloud/pipeshub-find-connector.png" alt="Your connectors page with Nextcloud found by search and its Set up button" style={{ display: 'block', margin: '0 auto' }} width="100%" />
  </Step>
  <Step title="Fill in the Authenticate tab">
    - **Instance name**: a label for this connection, such as `My Nextcloud`.
    - **Base URL**: your Nextcloud address, starting with `https://`, for example `https://cloud.example.com`. If Nextcloud lives under a sub-folder, include it (`https://example.com/nextcloud`). Use the address Nextcloud ends up on in your browser, without a slash at the end and without anything after it such as `/remote.php/...`.
    - **Username**: the name you sign in to Nextcloud with (the **Login** from Step 1). An email address works too, if that is how you sign in.
    - **App Password / Token**: the app password you copied in Step 1.

    Click **Next**.

    <img src="/images/connectors/nextcloud/pipeshub-authenticate.png" alt="Authenticate tab with Instance name, Base URL, Username and App Password / Token fields" style={{ display: 'block', margin: '0 auto' }} width="60%" />
  </Step>
  <Step title="Choose your settings on the Configure records tab">
    Pick how often to sync and, if you like, add filters. The defaults (sync every hour, everything in your Nextcloud) suit most people. See [Choose what to sync](#choose-what-to-sync) for what each setting does.

    <img src="/images/connectors/nextcloud/pipeshub-configure-records.png" alt="Configure records tab with Sync strategy, Sync interval, Batch Size, Enable Manual Indexing and Sync filters" style={{ display: 'block', margin: '0 auto' }} width="60%" />
  </Step>
  <Step title="Save and start syncing">
    Click **Save configuration**, then **Start syncing now**. If you choose **I'll do it later**, turn on **Sync enabled** on the connector's card when you're ready.

    PipesHub checks your app password only when the connector is turned on, not when you save. If something is wrong, you see a message straight away; see [Troubleshooting](#troubleshooting).

    <img src="/images/connectors/nextcloud/pipeshub-connector-card.png" alt="Nextcloud connector card showing Configuration Complete, Last synced and the Sync enabled toggle" style={{ display: 'block', margin: '0 auto' }} width="60%" />
  </Step>
</Steps>

The first sync reads your whole Nextcloud, so it can take a while if you have many files. Files become searchable as they are indexed.

## Choose what to sync

These are the settings on the **Configure records** tab.

| Setting | What it does |
|---|---|
| **Sync strategy** | **Scheduled** syncs automatically. **Manual** syncs only when you start a sync from the connector's card. |
| **Sync interval** | How often a scheduled sync runs. Default: 1 hour. |
| **Batch Size** | How many files PipesHub saves at a time (25, 50 or 100; default 50). Leave it as it is unless your administrator asks you to lower it. |
| **Enable Manual Indexing** | **On**: synced files are not made searchable until you choose them. **Off** (default): every synced file is made searchable. |
| **Modified Date** (sync filter) | Sync only files changed in a period you pick, such as the last 90 days, or before, after or between dates. Use it to skip old files. |
| **File Extensions** (sync filter) | Sync only certain file types (for example `pdf`, `docx`), or leave certain types out. Folders are always kept, so your folder structure stays the same. |

Add a sync filter with **Add filter**. If you add none, PipesHub syncs your whole Nextcloud. You can't pick individual folders, and there is no Created Date filter.

<Note>
  **Changing filters later.** You can only change the sync filters while the connector is turned off. Turn off **Sync enabled**, change the filters, save, and turn it back on. The next sync then re-checks your whole Nextcloud and removes from PipesHub the files the new filters leave out. Until that sync finishes, those files stay searchable.
</Note>

## What gets synced and how it stays up to date

**What is synced:** every file and folder in your Nextcloud, including files and folders others shared with you, within the filters you set. Search results link back to the file in Nextcloud.

**What is not synced:**
- Files someone shared with you with **Allow download** turned off. The owner chose that their content shouldn't leave Nextcloud, so PipesHub skips it. If the owner turns download off later, the file is removed from PipesHub.
- Files left out by your sync filters.

**How quickly changes show up:** each scheduled sync picks up what changed in Nextcloud since the last one: new, edited, renamed, moved, deleted and restored files, and files shared with you or unshared. With the default interval, a change shows up in PipesHub within about an hour. A file that is renamed or moved keeps its place in PipesHub; it isn't indexed again. A file deleted in Nextcloud is removed from PipesHub, and deleting a folder removes everything in it.

**A full re-check runs at least once a day.** If more than a day has passed since the last full check, the next sync re-reads your whole Nextcloud. This catches anything the quicker syncs missed.

**If something can't be read:** PipesHub never removes files because of a failed sync. If a sync fails, files already synced stay searchable, and the next sync tries again. A folder Nextcloud can't open right now (for example, external storage that is offline) keeps what was synced from it before.

**If your app password is revoked or stops working:** syncing stops and you get a notification ending in **Nextcloud app password rejected**. Files already synced stay searchable, but previews and downloads stop working. PipesHub stops using the rejected password, so Nextcloud doesn't start slowing down sign-ins from PipesHub. To fix it, see **App password rejected** under [Troubleshooting](#troubleshooting).

**Remote wipe:** if you or a Nextcloud admin choose **Wipe device** for the PipesHub app password in Nextcloud (**Devices & sessions**), PipesHub removes everything this connector synced, tells Nextcloud the wipe is done, and sends you a notification ending in **synced Nextcloud data removed**. Nextcloud then deletes the app password. To sync again, create a new app password and follow the steps under **App password rejected** in [Troubleshooting](#troubleshooting).

## Troubleshooting

Notifications from this connector start with the connector's instance name, for example **My Nextcloud: Nextcloud sync failed**.

<AccordionGroup>

<Accordion title="App password rejected">
  **What you see:** turning the connector on fails, or you get a notification ending in **Nextcloud app password rejected**.

  **Why:** the app password was mistyped, revoked, or is your normal login password, or the username is wrong.

  **Fix:**
  1. In Nextcloud, go to **Personal settings → Security → Devices & sessions** and create a new app password.
  2. In PipesHub, turn off **Sync enabled** on the connector's card. You can't change the password while the connector is on.
  3. Open the connector's settings, enter the new app password (and check the username), and save.
  4. Turn **Sync enabled** back on. PipesHub checks the password now and starts syncing again.
</Accordion>

<Accordion title="App password cannot read files">
  **What you see:** turning the connector on fails, or a notification ending in **Nextcloud app password cannot read files**.

  **Why:** the app password doesn't have filesystem access.

  **Fix:** in Nextcloud (**Personal settings → Security → Devices & sessions**), open the app password's **...** menu and turn on **Allow filesystem access**. Or create a new app password and enter it as described under **App password rejected** above.
</Accordion>

<Accordion title="The connector won't turn on because of the Base URL">
  **Why:** the address is wrong or isn't allowed.

  **Fix:** check that the Base URL:
  - starts with `https://`;
  - is the address Nextcloud ends up on in your browser (PipesHub doesn't follow redirects);
  - includes the sub-folder Nextcloud is installed under, if any, but nothing like `/remote.php/dav`;
  - has no slash at the end.

  If it is right, ask your PipesHub administrator whether the PipesHub server can reach your Nextcloud.
</Accordion>

<Accordion title="Nextcloud sync failed">
  **What you see:** a notification ending in **Nextcloud sync failed**, with the reason.

  **Why:** the sync couldn't finish, for example because Nextcloud was in maintenance mode or couldn't be reached.

  **Fix:** usually nothing; nothing was removed, and the next sync tries again. If it keeps failing, check that Nextcloud is up and reachable from the PipesHub server.
</Accordion>

<Accordion title="Some Nextcloud folders could not be read">
  **What you see:** a notification ending in **some Nextcloud folders could not be read**, naming the folders.

  **Why:** usually external storage that is offline, or a folder shared from another Nextcloud server that is down.

  **Fix:** none needed in PipesHub. What was synced from those folders is kept, and they are read again at the next daily full check. Their files may be out of date until then.
</Accordion>

<Accordion title="Nextcloud Activity app missing">
  **What you see:** a notification ending in **Nextcloud Activity app missing**.

  **Why:** the Activity app is turned off in Nextcloud, so PipesHub can't see changes one by one. Every sync re-reads your whole Nextcloud, which is slower.

  **Fix:** ask your Nextcloud admin to enable the Activity app.
</Accordion>

<Accordion title="Some Nextcloud changes not applied">
  **What you see:** a notification ending in **some Nextcloud changes not applied**.

  **Why:** some changes failed on five syncs in a row.

  **Fix:** usually nothing. PipesHub keeps retrying them on every sync. Until they go through, those files may be missing or out of date in PipesHub.
</Accordion>

<Accordion title="Changes only show up once a day">
  **Why:** in Nextcloud's notification settings, you limited notifications about new and changed files to your favorite files. Nextcloud then reports only changes to favorites, so other changes reach PipesHub only with the daily full check.

  **Fix:** in Nextcloud, go to **Personal settings → Notifications** and remove that limit.
</Accordion>

<Accordion title="Search doesn't find my Nextcloud files">
  - **Someone else set up the connector.** Only the person who created a Nextcloud connector can search what it syncs. Set up your own.
  - **The first sync is still running.** Check **Last synced** on the connector's card and wait for it to finish.
  - **Enable Manual Indexing is on.** Synced files aren't searchable until you choose them.
  - **A sync filter leaves the file out**, or the file is shared with download turned off.
</Accordion>

</AccordionGroup>

<Accordion title="Details for administrators">
  - **Plain HTTP.** The Base URL must use `https://`. If a Nextcloud server is only reachable over `http://` on a network you trust, you can allow it by setting `PIPESHUB_NEXTCLOUD_ALLOW_INSECURE_HTTP=true` on the PipesHub server. The app password is then sent unencrypted.
  - **Blocked addresses.** PipesHub never connects to its own server (`localhost`), link-local addresses or cloud metadata addresses. If `PIPESHUB_BLOCK_PRIVATE_ADDRESSES` is set, private network addresses are refused too. The Base URL can't contain `?`, `#`, or a user name and password, and redirects (even from `http://` to `https://` on the same host) are refused.
  - **Rejected passwords.** After Nextcloud rejects an app password, PipesHub stops sending it until the user turns the connector off and on. Nextcloud's brute-force protection counts rejected sign-ins per address, so repeated attempts would slow down every Nextcloud connector on the same PipesHub server.
  - **Memory.** A full check holds the drive's whole file list in memory, about 6 KB per file (about 60 MB for 10,000 files). It builds that list before it applies sync filters or **Batch Size**, so neither setting reduces it. For very large drives, give the server that runs PipesHub's connectors enough memory.
</Accordion>
