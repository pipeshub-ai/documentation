0.10.0 is a large release (about 330 merged PRs since 0.9.1) with three main themes. First, deleted records can now go to a trash and be restored, behind a feature flag. Second, an entity layer on the knowledge graph, with agent tools to query it, is built out through several phases. Third, a broad hardening pass covers authentication, org scoping, SSRF, the code sandbox and the Docker socket, plus many fixes so that connectors remove content that was deleted or filtered out at the source.

Operators should read the upgrade notes below. Several defaults are now stricter (sandbox mode, sandbox networking, custom STDIO MCP servers, service tokens on the parsing and extraction services, CORS), and the app container now runs as non-root and reaches Docker through a policy proxy.

## Highlights

### Soft delete: a trash for records, with restore and purge

Deleted records can move to a trash instead of disappearing, behind the `ENABLE_SOFT_DELETE` flag. The work landed as a series: the record data model with live-only reads ([#3695](https://github.com/pipeshub-ai/pipeshub-ai/pull/3695)), moving deleted records to the trash ([#3718](https://github.com/pipeshub-ai/pipeshub-ai/pull/3718)), restoring them ([#3799](https://github.com/pipeshub-ai/pipeshub-ai/pull/3799)), purging records that stay in the trash past the retention period ([#3847](https://github.com/pipeshub-ai/pipeshub-ai/pull/3847)), an end-to-end test of the acceptance checklist ([#3853](https://github.com/pipeshub-ai/pipeshub-ai/pull/3853)) and a "Recently deleted" page for collections ([#3884](https://github.com/pipeshub-ai/pipeshub-ai/pull/3884)) — all @shekharkadyan. Follow-ups make a vectors-cleanup event the broker refuses count as unpublished ([#3901](https://github.com/pipeshub-ai/pipeshub-ai/pull/3901)), refuse moving, creating or uploading into a trashed folder ([#3973](https://github.com/pipeshub-ai/pipeshub-ai/pull/3973)), keep trashed tables out of the agent full-record tool's foreign-key lists ([#3903](https://github.com/pipeshub-ai/pipeshub-ai/pull/3903)) and rename the restore refusal field to `blockedRecordId` ([#3986](https://github.com/pipeshub-ai/pipeshub-ai/pull/3986) — @siddhant-pipeshub).

### Knowledge-graph entities and entity tools for agents

The knowledge graph gains an entity index and agent tools to search it. It started with entity tools and entity indexing ([#3308](https://github.com/pipeshub-ai/pipeshub-ai/pull/3308) — @tushar1245) and was extended in phases by @abhishekgml1991: retried connector entity cleanup and write outcomes (Phase C, [#3769](https://github.com/pipeshub-ai/pipeshub-ai/pull/3769)), permission checks inside the graph query and cleaner tool output (Phase D, [#3770](https://github.com/pipeshub-ai/pipeshub-ai/pull/3770)), concurrent enrichment and resolver decisions (Phase E, [#3771](https://github.com/pipeshub-ai/pipeshub-ai/pull/3771)), an in-memory vector fake and an entity-resolution eval (Phase F, [#3772](https://github.com/pipeshub-ai/pipeshub-ai/pull/3772)) and top-3 merge candidates (Phase G, [#3773](https://github.com/pipeshub-ai/pipeshub-ai/pull/3773)). The release also adds a rebuild of the entity index from the graph ([#3759](https://github.com/pipeshub-ai/pipeshub-ai/pull/3759)) and reversible merging of duplicate taxonomy nodes, with migration of legacy ones ([#3767](https://github.com/pipeshub-ai/pipeshub-ai/pull/3767)).

### Security hardening across the platform

A large share of this release closes security gaps found in review and by advisories: org scoping on records, connectors and crawling routes; SSRF protection for document images and Web/RSS fetches; signed download URLs bound to the redeeming user; a fail-closed sandbox mode; hardened session, SAML and password-reset handling; masking of stored secrets; and a service token required on the parsing and extraction services. The full list is under [Security & authentication](#security--authentication).

### Per-connector indexing lanes

Indexing now gives each connector its own Redis Streams lane so one busy connector cannot starve the others. It shipped in three stacked PRs: recording lanes ([#3979](https://github.com/pipeshub-ai/pipeshub-ai/pull/3979)), assigning them at connector creation and freeing them at delete ([#3980](https://github.com/pipeshub-ai/pipeshub-ai/pull/3980)), and switching assigned lanes on ([#3982](https://github.com/pipeshub-ai/pipeshub-ai/pull/3982)). On Kafka, the consumer reads past a connector at its cap ([#3977](https://github.com/pipeshub-ai/pipeshub-ai/pull/3977)), and events for a turned-off or removed connector are settled as they are read ([#3976](https://github.com/pipeshub-ai/pipeshub-ai/pull/3976)) — all @shekharkadyan.

### Connectors remove what was deleted or filtered out at the source

Many connectors previously left stale records behind. This release fixes removal for deleted, trashed or filtered-out items in Confluence (Cloud, Data Center and personal), Zammad, Jira Personal, Drive Workspace, Nextcloud, Bookstack, Object Store (S3-style buckets and containers), Web, RSS, Snowflake and Outlook Personal on ArangoDB. See [Connectors](#connectors) for each.

### AI models: discovery, reasoning effort and prompt caching

Admins can discover a provider's models and add several at once ([#4012](https://github.com/pipeshub-ai/pipeshub-ai/pull/4012), [#4054](https://github.com/pipeshub-ai/pipeshub-ai/pull/4054) — @abhishekgml1991). A model can carry its own default reasoning effort, and the chat picker shows it ([#3828](https://github.com/pipeshub-ai/pipeshub-ai/pull/3828), [#3837](https://github.com/pipeshub-ai/pipeshub-ai/pull/3837) — @shekharkadyan). The agent loop adds provider prompt caching for prompts and tool definitions ([#4038](https://github.com/pipeshub-ai/pipeshub-ai/pull/4038) — @abhishek-pipeshub).

### LLM-driven grep over stored content

Agents can match patterns over stored records using an LLM-driven grep with permission-aware scoping ([#3568](https://github.com/pipeshub-ai/pipeshub-ai/pull/3568) — @vishwjeet-pawar03). Follow-ups keep same-named folder and page twins apart ([#3761](https://github.com/pipeshub-ai/pipeshub-ai/pull/3761)), block `xargs` argument injection ([#3784](https://github.com/pipeshub-ai/pipeshub-ai/pull/3784)), store record JSON as UTF-8 so non-ASCII text matches ([#3763](https://github.com/pipeshub-ai/pipeshub-ai/pull/3763)), and keep a cited grep hit's name, type and quote ([#4014](https://github.com/pipeshub-ai/pipeshub-ai/pull/4014)).

### Artifacts gallery and email delivery

An All Artifacts gallery with ACL-aware listing ([#3427](https://github.com/pipeshub-ai/pipeshub-ai/pull/3427) — @abhishekgml1991) gains PPTX rendering ([#4056](https://github.com/pipeshub-ai/pipeshub-ai/pull/4056)). Email is now delivered asynchronously through the message broker ([#2906](https://github.com/pipeshub-ai/pipeshub-ai/pull/2906) — @anupPradhan0), with follow-up fixes for duplicate and lost sends in the consumer ([#3743](https://github.com/pipeshub-ai/pipeshub-ai/pull/3743)).

## Breaking changes & upgrade notes

- **Sandbox is stricter by default.** `SANDBOX_MODE` unset or unknown now fails closed ([#3725](https://github.com/pipeshub-ai/pipeshub-ai/pull/3725)); `SANDBOX_MODE=local` is refused unless `SANDBOX_ALLOW_LOCAL=true` ([#3803](https://github.com/pipeshub-ai/pipeshub-ai/pull/3803)); code-execution network access is off by default and the egress bridge is firewalled ([#3780](https://github.com/pipeshub-ai/pipeshub-ai/pull/3780)); symlink tar members are dropped and user and file-size limits are pinned ([#3810](https://github.com/pipeshub-ai/pipeshub-ai/pull/3810)).
- **Docker access goes through a proxy and the app runs as non-root** ([#3782](https://github.com/pipeshub-ai/pipeshub-ai/pull/3782)). The proxy allow-lists the container create body ([#3811](https://github.com/pipeshub-ai/pipeshub-ai/pull/3811)) and refuses header injection and ambiguous framing ([#3816](https://github.com/pipeshub-ai/pipeshub-ai/pull/3816)). Helm routes the DinD sandbox through the same policy proxy ([#3888](https://github.com/pipeshub-ai/pipeshub-ai/pull/3888)). Review custom Docker or volume setups.
- **Custom STDIO MCP servers are an operator opt-in**, and catalog commands are pinned ([#3887](https://github.com/pipeshub-ai/pipeshub-ai/pull/3887)).
- **Parsing and extraction services require a service token** ([#3818](https://github.com/pipeshub-ai/pipeshub-ai/pull/3818)). Direct callers of those services must send one.
- **Wildcard credentialed CORS removed** from the query and connector services ([#3890](https://github.com/pipeshub-ai/pipeshub-ai/pull/3890)).
- **Signed download URLs** are bound to the redeeming user ([#3723](https://github.com/pipeshub-ai/pipeshub-ai/pull/3723)) and capped at 7 days ([#3790](https://github.com/pipeshub-ai/pipeshub-ai/pull/3790)).
- **Behavior changes on API responses.** Admin-only routes answer 403 instead of 400 ([#3696](https://github.com/pipeshub-ai/pipeshub-ai/pull/3696), [#3827](https://github.com/pipeshub-ai/pipeshub-ai/pull/3827)); org-wide crawling schedule lists are admin-gated ([#3814](https://github.com/pipeshub-ai/pipeshub-ai/pull/3814)); stats on an unopenable connector answer 404 ([#3922](https://github.com/pipeshub-ai/pipeshub-ai/pull/3922)); connector config responses mask stored secrets ([#3923](https://github.com/pipeshub-ai/pipeshub-ai/pull/3923)); personal connectors are listed only for their creator ([#3921](https://github.com/pipeshub-ai/pipeshub-ai/pull/3921)); two record-creation routes that could only answer 500 are removed ([#3933](https://github.com/pipeshub-ai/pipeshub-ai/pull/3933)).
- **Group names are unique per org**, enforced in the database ([#3698](https://github.com/pipeshub-ai/pipeshub-ai/pull/3698), [#3638](https://github.com/pipeshub-ai/pipeshub-ai/pull/3638)). Existing duplicate active names may need renaming.
- **Soft delete is behind `ENABLE_SOFT_DELETE`** (see Highlights); per-connector indexing lanes are switched on by default ([#3982](https://github.com/pipeshub-ai/pipeshub-ai/pull/3982)).
- **Node API no longer publishes record events** (unused publisher removed in [#3982](https://github.com/pipeshub-ai/pipeshub-ai/pull/3982)).
