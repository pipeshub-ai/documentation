# Internal Services: Public URLs

PipesHub stores two public URLs: one for the frontend (the web app) and one for the connector service. There is no settings page for them. Set them with environment variables or with the Configuration Manager API.

<Info>
  **Workspace > Services** in the app is a health monitor for the infrastructure and application services. It does not edit these URLs.
</Info>

## Frontend public URL

The frontend public URL is the address users open in the browser. PipesHub uses it to build OAuth redirect URIs for connectors, actions and MCP servers, and to build links back to records and chats.

Set it in one of these ways:

- **Environment variable:** set `FRONTEND_PUBLIC_URL` in your `.env` file (for example `https://pipeshub.example.com`) and restart. When it is set, it replaces the stored value each time the service starts.
- **API:** send `POST /api/v1/configurationManager/frontendPublicUrl` with `{"url": "https://pipeshub.example.com"}`. This needs an admin user and the `config:write` scope. See [Configuration Manager](/system-overview/configuration-manager).

<Warning>
  Set the frontend public URL before you configure OAuth connectors. The Redirect URI that PipesHub shows for a connector is built from it, and the URI you register with the vendor must match exactly.
</Warning>

## Connector public URL

The connector public URL is the public address of the connector service. The web app is allowed to call it from the browser.

Set it in one of these ways:

- **Environment variable:** set `CONNECTOR_PUBLIC_BACKEND` and restart. When it is set, it replaces the stored value each time the service starts.
- **API:** send `POST /api/v1/configurationManager/connectorPublicUrl` with `{"url": "https://connectors.example.com"}`. This needs an admin user and the `config:write` scope.
