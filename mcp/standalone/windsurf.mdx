After [`init`](/mcp/standalone/quickstart), Windsurf can search your team's documents and, once you have indexed a repository, ask about its code. This page covers what `init` changes for Windsurf and how to check it.

## What `init` writes

| File | What |
|---|---|
| `~/.codeium/windsurf/mcp_config.json` | The `pipeshub` entry under `mcpServers` |
| `.windsurf/rules/pipeshub.md` in your repository | A rule Cascade applies when a request matches its description. Only with `init --project` |

Windsurf has no user-level instruction file for `init` to write, so run `init --project` in each repository where you want the rule. Windsurf has no slash commands from `init`: ask in plain words.

## Check that Windsurf sees PipesHub

<Steps>
  <Step title="Restart Windsurf">
    Quit and reopen it.
  </Step>
  <Step title="Open the MCP list in Cascade">
    Open the MCP servers list from Cascade (the plugins icon, or **Settings > Cascade > MCP Servers**). `pipeshub` should be listed with its tools. If it is not, use the refresh button there.
  </Step>
  <Step title="Ask">
    Ask Cascade to index this repository with PipesHub, then ask who calls a function.
  </Step>
</Steps>

## Without `init`

Start the stack and sign in first ([Set up one agent by hand](/mcp/standalone/quickstart#set-up-one-agent-by-hand)), then add the entry to `~/.codeium/windsurf/mcp_config.json`:

```json
{
  "mcpServers": {
    "pipeshub": {
      "command": "npx",
      "args": ["-y", "@pipeshub-ai/mcp@>=4.7.0", "start", "--server-url", "http://127.0.0.1:3000"],
      "env": { "PIPESHUB_MCP_CHAT": "off" }
    }
  }
}
```

## Undo

```bash
npx @pipeshub-ai/standalone uninstall --client windsurf
```

This removes only what `init` added for Windsurf, from the files above. A backup of each file `init` changed is in `~/.config/pipeshub/backups/`. To remove everything, see [Undo everything](/mcp/standalone/quickstart#undo-everything).
