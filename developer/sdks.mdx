PipesHub has official SDKs for **Python**, **TypeScript** and **Go**. Each one wraps the [PipesHub API](/developer/api-reference) with typed requests and responses, so your editor completes method names and fields and catches mistakes before you run the code. The SDKs also handle authentication, retries, streaming responses and file uploads for you.

The three SDKs are generated from the same API specification as the [API reference](/developer/api-reference), share version numbers, and offer the same methods under each language's naming style.

## Connect to PipesHub

Every request needs a token. Create a [personal access token](/developer/personal-access-tokens) in PipesHub, or get an access token from an [OAuth 2.0 app](/developer/oauth2), and put it in an environment variable:

```bash
export PIPESHUB_BEARER_AUTH="<your token>"
```

Then create a client. It connects to PipesHub Cloud (`https://app.pipeshub.com/api/v1`) by default. For a self-hosted instance, pass your instance's URL followed by `/api/v1`:

<CodeGroup>
```python Python
import os
from pipeshub_sdk import Pipeshub, models

pipeshub = Pipeshub(
    server_url="https://pipeshub.example.com/api/v1",  # leave out for PipesHub Cloud
    security=models.Security(bearer_auth=os.environ["PIPESHUB_BEARER_AUTH"]),
)
```

```typescript TypeScript
import { Pipeshub } from "@pipeshub-ai/sdk";

const pipeshub = new Pipeshub({
  serverURL: "https://pipeshub.example.com/api/v1", // leave out for PipesHub Cloud
  security: { bearerAuth: process.env["PIPESHUB_BEARER_AUTH"] ?? "" },
});
```

```go Go
import (
	"os"

	pipeshub "github.com/pipeshub-ai/pipeshub-sdk-go/v2"
	"github.com/pipeshub-ai/pipeshub-sdk-go/v2/models/components"
)

s := pipeshub.New(
	pipeshub.WithServerURL("https://pipeshub.example.com/api/v1"), // leave out for PipesHub Cloud
	pipeshub.WithSecurity(components.Security{
		BearerAuth: pipeshub.Pointer(os.Getenv("PIPESHUB_BEARER_AUTH")),
	}),
)
```
</CodeGroup>

The examples below use this client. The token decides what the calls can see: results only include content the token's user has access to, and each method needs the scope listed on its endpoint page.

## Basic usage

### Search your company's knowledge

`retrieve` returns the passages that best match a query, each with its record and a citation link. It is the call most RAG apps and agents start with. See [Retrieval API](/developer/retrieval-api) for filters and how results are ranked.

<CodeGroup>
```python Python
res = pipeshub.semantic_search.retrieve(query="How do we roll back a canary deploy?", limit=5)

for chunk in res.chunks:
    print(chunk.record.name, chunk.citation.url)
    print(chunk.text)
```

```typescript TypeScript
const { chunks } = await pipeshub.semanticSearch.retrieve({
  query: "How do we roll back a canary deploy?",
  limit: 5,
});

for (const chunk of chunks) {
  console.log(chunk.record.name, chunk.citation.url);
  console.log(chunk.text);
}
```

```go Go
res, err := s.SemanticSearch.Retrieve(ctx, components.RetrieveRequest{
	Query: "How do we roll back a canary deploy?",
	Limit: pipeshub.Int64(5),
})
if err != nil {
	log.Fatal(err)
}

for _, chunk := range res.RetrieveResponse.Chunks {
	if chunk.Citation.URL != nil {
		log.Println("Source:", *chunk.Citation.URL)
	}
	log.Println(chunk.Text)
}
```
</CodeGroup>

### Ask a question

`createConversation` starts a chat, waits for PipesHub to answer from your company's knowledge, and returns the conversation. The last message is the answer, and its `citations` list the sources.

<CodeGroup>
```python Python
res = pipeshub.conversations.create_conversation(query="What is our on-call rotation?")

messages = res.result.conversation.messages or []
print(messages[-1].content)
```

```typescript TypeScript
const { result } = await pipeshub.conversations.createConversation({
  query: "What is our on-call rotation?",
});

const answer = result.conversation.messages?.at(-1);
console.log(answer?.content);
```

```go Go
res, err := s.Conversations.CreateConversation(ctx, components.CreateConversationRequest{
	Query: "What is our on-call rotation?",
})
if err != nil {
	log.Fatal(err)
}

messages := res.CreateConversationResponse.Conversation.Messages
if answer := messages[len(messages)-1]; answer.Content != nil {
	log.Println(*answer.Content)
}
```
</CodeGroup>

To show the answer while it is being written, use `streamChat` instead. Streaming methods return the server-sent events as they arrive: loop over them with `for` in Python, `for await` in TypeScript, and `Next()` and `Value()` in Go.

### Handle errors

A failed request raises an error that carries the HTTP status and the API's error body. The body has a machine-readable `code`, a `message` and a `requestId` to quote in a bug report. See [Rate limits and API errors](/additional-resources/rate-limits-and-errors) for what each status means.

<CodeGroup>
```python Python
from pipeshub_sdk import errors

try:
    res = pipeshub.semantic_search.retrieve(query="quarterly revenue")
except errors.ErrorResponse as e:
    print(e.status_code, e.data.error.code, e.data.error.message)
except errors.PipeshubError as e:
    print(e.status_code, e.body)
```

```typescript TypeScript
import * as errors from "@pipeshub-ai/sdk/models/errors";

try {
  await pipeshub.semanticSearch.retrieve({ query: "quarterly revenue" });
} catch (error) {
  if (error instanceof errors.ErrorResponse) {
    console.log(error.statusCode, error.data$.error.code, error.data$.error.message);
  } else if (error instanceof errors.PipeshubError) {
    console.log(error.statusCode, error.body);
  } else {
    throw error; // connection failures and anything else
  }
}
```

```go Go
_, err := s.SemanticSearch.Retrieve(ctx, components.RetrieveRequest{Query: "quarterly revenue"})

var apiErr *apierrors.ErrorResponse
var other *apierrors.APIError
switch {
case errors.As(err, &apiErr):
	log.Println(apiErr.Error_.Code, apiErr.Error_.Message)
case errors.As(err, &other):
	log.Println(other.StatusCode, other.Body)
case err != nil:
	log.Fatal(err) // connection failures and anything else
}
```
</CodeGroup>

The SDKs do not retry failed calls unless you ask them to. Pass a retry configuration (backoff with a maximum elapsed time) to the client to retry every call, or to a single call. Retries apply to `429`, `500`, `502`, `503` and `504` responses. See the SDK's README for the options.

### Use with AI frameworks

The SDKs include ready-made integrations that feed PipesHub search results to a model:

- **Python:** retrievers for LangChain and LlamaIndex. Install them with `pip install "pipeshub-sdk[langchain]"` or `pip install "pipeshub-sdk[llamaindex]"`.
- **TypeScript:** `pipeshubRetrieveTool` from `@pipeshub-ai/sdk/integrations/ai-sdk`, a search tool for the [Vercel AI SDK](https://ai-sdk.dev) 5 and later.

## Versions

The three SDKs are released together with the same version number. These docs describe the latest release. The changes in each release are on the releases page of each SDK: [Python](https://github.com/pipeshub-ai/pipeshub-sdk-python/releases), [TypeScript](https://github.com/pipeshub-ai/pipeshub-sdk-typescript/releases), [Go](https://github.com/pipeshub-ai/pipeshub-sdk-go/releases).

<Accordion title="Upgrading from 1.x to 2.x">
- **Retrieval.** `semanticSearch.retrieve` was added.
- **Connectors.** The `connectorRegistry`, `connectorInstances`, `connectorConfiguration`, `connectorControl`, `connectorFilters`, `connectorOAuth` and `oAuthConfiguration` namespaces were added.
- **Projects.** The `projects` namespace was removed. Check your code for it before you upgrade.
- **Go module path.** The Go module moved to `github.com/pipeshub-ai/pipeshub-sdk-go/v2`. Update your imports.
</Accordion>
