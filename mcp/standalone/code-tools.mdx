PipesHub builds a graph of the code in an indexed repository (files, symbols, and the calls, imports and inheritance between them). Twelve `pipeshub_code_*` tools query it, and the bridge adds one more tool, `index_workspace`, that puts your repository in.

The tools are listed only for a sign-in that can read code (`code:read`) and only once at least one repository is indexed. A repository you have not indexed has no code tools, so index first: run `pipeshub index`, or let the agent call `index_workspace`.

## When to use which

| The question | Use |
|---|---|
| Who calls this function? What does it call? Who imports this file? | `pipeshub_code_neighbours` |
| What could break if I change this? | `pipeshub_code_impact` |
| What could this diff or pull request break? | `pipeshub_code_impact_of_diff` |
| Who changed this file, and why? | `pipeshub_code_history` |
| Where is `X` defined? | `pipeshub_code_search` |
| Where is the code that does this, when I do not know its names? | `pipeshub_code_semantic_search` |
| Where does this string, config key or pattern appear? | `pipeshub_code_search` with `mode: "text"` or `"regex"` |
| Who calls into this library? | `pipeshub_code_search` with `mode: "external"` |
| What is in this directory or file? | `pipeshub_code_symbols` |
| What is in this file, without the bodies? | `pipeshub_code_outline` |
| Show me this function or these lines | `pipeshub_code_read` |
| How does A reach B? | `pipeshub_code_path` |
| Where does the program start? | `pipeshub_code_entry_points` |
| What is indexed? | `pipeshub_code_repos` |
| What the team decided, discussed or filed about it | `pipeshub_search`, then `pipeshub_get_record_content` |
| The file you are about to edit | Read the file in your editor. The indexed copy can lag behind your working tree |

## Tools

All code tools except `pipeshub_code_repos` take a `repo` (`owner/name`) from `pipeshub_code_repos`. The tools that also take `record_id` (a code file's `recordId` from `pipeshub_search`) can be called with that instead of `repo` and `file_path`. Symbols are named as results show them, such as `function:parse_config` or `method:Client.fetch`: copy the name from a result. Test files are left out unless `include_tests` is true.

| Tool | Main arguments | Returns |
|---|---|---|
| `pipeshub_code_repos` | none | The repositories you can read |
| `pipeshub_code_symbols` | `repo`, `select` (a directory, a file or a glob), `kinds`, `limit` (1-500) | The children of a directory, or the symbols a file defines with line ranges, ranked by how connected each is |
| `pipeshub_code_neighbours` | `repo`, `file_path` or `record_id`, `qualified_name`, `direction` (`inbound`, `outbound`, `any`; default `any`), `edge_types`, `depth` (1-3, default 1), `limit` (1-200), `offset` | Callers, callees, imports and inheritance, each with file, line range and name |
| `pipeshub_code_read` | `repo`, `file_path` or `record_id`, `qualified_name` or `lines` (`"40-80"`), `max_lines` (1-2000) | One symbol, a line range, or a file up to `max_lines` (it says where it stopped) |
| `pipeshub_code_path` | `repo`, `file_path_a`, `qualified_name_a`, `file_path_b`, `qualified_name_b`, `max_depth` (1-8), `edge_types`, `undirected` | How A reaches B, hop by hop. `reversed: true` means B reaches A |
| `pipeshub_code_search` | `repo`, `pattern` (up to 200 characters), `mode` (`identifier`, the default, `text`, `regex` or `external`), `name` (`external` only), `path` (optional), `limit` (1-200) | Every definition of a name; matching lines (with a `path`, in at most 1,000 files under it; without one, in the files the keyword index proposes, and `complete: false` when a match may be missing); or, for `external`, the code that calls into a library module |
| `pipeshub_code_semantic_search` | `repo`, `query` (plain words, up to 500 characters), `limit` (1-50, default 15) | Symbols, classes and files ranked by meaning, best first, each with a `score` |
| `pipeshub_code_outline` | `repo`, `file_path` or `record_id` | Classes, functions and methods with signatures and line ranges, no bodies |
| `pipeshub_code_impact` | `repo`, `file_path` or `record_id`, `qualified_name`, `depth` (1-5, default 2), `edge_types` (`CALLS`, `INDIRECT_CALL`, `IMPORTS_FROM`, `INHERITS`, `IMPLEMENTS`, `OVERRIDES`) | What calls, imports or builds on a symbol, followed backwards and grouped by file, with tests apart in `impacted_tests` |
| `pipeshub_code_impact_of_diff` | `repo`, `patch` (a unified diff, up to 2,000,000 characters), `depth` (1-5, default 2) | The symbols the diff changes, the files and tests that reach them, and `untested_callers`. Lines are matched against the indexed commit |
| `pipeshub_code_history` | `repo`, `file_path` or `record_id`, `qualified_name`, `limit` (1-100, default 20) | The indexed pull or merge requests that changed the file, newest first, with author, reviewers asked, who merged it and the tickets it names |
| `pipeshub_code_entry_points` | `repo`, `limit` (1-200) | Functions nothing in the repository calls (routes, command lines, jobs, hooks), conventional names first |

`edge_types` on `pipeshub_code_neighbours` and `pipeshub_code_path` takes any of `CALLS`, `INDIRECT_CALL`, `IMPORTS`, `IMPORTS_FROM`, `RE_EXPORTS`, `EXPORTS`, `INHERITS`, `IMPLEMENTS`, `OVERRIDES`, `CONTAINS`, `DEFINES` and `METHOD`; leave it out to follow all of them.

### Coverage

Calls and imports across files are resolved through imports for Python, JavaScript, TypeScript, Java, Go, C#, PHP, Rust, C and C++. Other languages get calls matched by name. Links across languages or over HTTP are not in the graph. When an answer may be incomplete, the result carries a `coverage` field: confirm an empty result with `pipeshub_search` or by searching the files before relying on it.

## `index_workspace`

Added by the local bridge, not by the server, so it exists for every agent set up with `init --local`.

| Argument | Description |
|---|---|
| `path` | A folder inside a git repository. Only needed when the client does not share its open folders; otherwise the open folders are used |
| `waitSeconds` | How long to wait for indexing to finish before reporting its status. Default 20, up to 300. `0` returns right after the files are sent |

It sends the text files git lists that changed since last time, and returns per folder the repository name, files, files sent and skipped, and the indexing state. It is incremental, so it is safe to call again. If the client shares no folders and you pass no `path`, it says so and sends nothing. A subfolder of a repository indexes the whole repository. See [Index a repository](/mcp/standalone/quickstart#index-a-repository) for what is and is not sent.

## What the agent is told

`init --local` installs a short instruction text for each client (under 2,000 characters) that teaches the agent to:

- use the code tools for questions about the repository's structure, and `pipeshub_search` for what the team knows;
- call `index_workspace` first when the repository is not indexed or has changed a lot;
- keep calls small: set `limit`, use `depth` 1 or 2, outline before reading, read a symbol or line range rather than a whole file;
- cite results as repository, file path and line range, and say so when a `coverage` note warns of an incomplete answer.

A search hit for an indexed file links to its record page in your local PipesHub (`http://127.0.0.1:3000/record/<recordId>`): the bridge puts that link in place of the repository's internal address, which a browser cannot open. Cite the repository, file path and line range.

## Slash commands

| Client | Commands |
|---|---|
| Claude Code | `/pipeshub-index` and `/pipeshub-code <question>` |
| Gemini CLI | `/pipeshub:index` and `/pipeshub:code <question>` |

`index` indexes the current repository. `code` answers the question with the code tools and indexes first if needed. Other clients have the tools and the instruction text but no commands.
