Your AI agent application requires SMTP configuration to enable email-based features like One-Time Password (OTP) authentication, password reset, and notifications.

<Callout type="info">
  SMTP (Simple Mail Transfer Protocol) configuration is essential for all
  email-based functionality in your application.
</Callout>

When properly configured, your application can send automated emails to users for:

- One-Time Password (OTP) authentication
- Password reset requests
- Send invitations to the users to your organisation

## Configuring SMTP

Email is not part of the first-time onboarding steps. Admins set it up afterwards, or change it later, under **Workspace** > **Mail**.

<Steps>
  <Step title="Open Mail">
    In the sidebar, open **Workspace settings** and select **Mail**. This page is visible to admins only.
  </Step>
  <Step title="Open the SMTP settings">
    Click the settings (gear) icon on the **SMTP** row. The **Configure SMTP settings** panel opens on the right.

    <p align="center">
      <img src="/images/product/workspace/mail-settings.png" alt="Mail page with the SMTP row marked Not configured and its settings icon" width="100%" />
    </p>
  </Step>
  <Step title="Enter the settings">
    - **SMTP host** (*required*) - The address of your email server (e.g., smtp.gmail.com)
    - **Port** (*required*, 1 to 65535, default 587)
    - **From email address** (*required*) - The address that appears as the sender
    - **Username** and **Password** (optional) - For servers that need authentication

    <p align="center">
      <img src="/images/smtp/smtp_auth_config_dialog-new.png" alt="Configure SMTP settings dialog on the Mail page" width="100%" />
    </p>
  </Step>
  <Step title="Save">
    Click **Save**. PipesHub connects to the server and signs in with these settings before it stores them. If the server accepts them, the Mail page shows SMTP as **Configured**.
  </Step>
</Steps>

<Note>
  There is no test-send button. Saving checks the connection and login only; it does not send an email. To confirm delivery, trigger a real email, for example invite a user or use **Forgot password**.
</Note>

### What Save checks

The check gives up after 10 seconds. If the server refuses the settings, nothing is saved and the panel shows one of three fixed messages:

| Message | Meaning |
| --- | --- |
| "The mail (SMTP) server rejected this username or password. Check them, then save again." | The server was reached but refused the login. |
| "PipesHub couldn't reach the mail (SMTP) server at this host and port. Check them and that PipesHub can connect to the server, then save again." | The host or port is wrong, the server did not answer in time, or PipesHub has no network route to it. |
| "The mail (SMTP) server didn't accept a connection with these settings. Check the host, port, username and password, then save again." | Any other refusal. |

Port 465 uses TLS from the first byte. Other ports upgrade to TLS with STARTTLS when the server offers it.

## Common SMTP Providers

The table below lists settings for popular email providers:

| Provider           | SMTP Host                       | Port | Security |
| ------------------ | ------------------------------- | ---- | -------- |
| Gmail              | smtp.gmail.com                  | 587  | TLS      |
| Outlook/Office 365 | smtp.office365.com              | 587  | TLS      |
| Amazon SES         | email-smtp.region.amazonaws.com | 587  | TLS      |
| SendGrid           | smtp.sendgrid.net               | 587  | TLS      |

<Callout type="warning">
  For Gmail and some other providers, you may need to create an "App Password"
  instead of using your regular account password.
</Callout>

## Best Practices

For optimal SMTP configuration:

- Use a dedicated email address for system notifications (e.g., noreply@yourcompany.com)
- Check with your email provider for specific SMTP settings and requirements
- Confirm delivery after setup by sending a real email, such as a user invitation
- Use secure connections when possible (Port 465 for SSL or 587 for TLS)
- Check spam filters if users report not receiving emails

## Troubleshooting

<Callout type="error">
  If users are not receiving system emails, try these troubleshooting steps:
</Callout>

1. Verify your SMTP settings are correct
2. Ensure the "From Email Address" is properly configured
3. Check if your email provider restricts automated sending
4. Look for error messages in your application logs
5. Test your SMTP server connection using external tools
6. If Save fails, read the message in the panel (see What Save checks above)
