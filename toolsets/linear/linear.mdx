## Overview

The Linear toolset lets PipesHub agents act in Linear rather than only read from it. It exposes **9 tools**.

If you want Linear content to be searchable instead, you need a [connector](/connectors/overview). Connectors index data; toolsets perform actions. Many teams use both.

## Setting it up

Toolsets authorise separately from connectors, even where you already have a connector for the same service. A connector indexes data for search; a toolset lets an agent act.

1. In PipesHub, go to **Workspace settings → Connectors → Your Connectors** and find this integration.
2. Select **Setup** and copy the **redirect URI** that PipesHub displays. It ends with the capitalised toolset name, and it must be copied exactly.
3. Create an OAuth application in the provider's developer console and register that redirect URI against it.
4. Copy the client ID and client secret back into PipesHub and save.
5. Select **Authorize** and complete the provider's consent screen.

<Warning>
The redirect URI must match character for character — scheme, host, port, and the capitalisation of the name at the end. A mismatch is the most common cause of a failed authorisation.
</Warning>

## Available Tools

| Tool | What it does |
|------|--------------|
| `linear.create_issue` | Create a new Linear issue |
| `linear.delete_issue` | Delete a Linear issue |
| `linear.get_issue` | Get a Linear issue by ID |
| `linear.get_issues` | List Linear issues |
| `linear.get_team` | Get a Linear team by ID |
| `linear.get_teams` | List Linear teams |
| `linear.get_user` | Get a Linear user by ID |
| `linear.get_viewer` | Get current authenticated Linear user |
| `linear.update_issue` | Update a Linear issue |

## Using it in an agent

1. Open **Agents** and create or edit an agent.
2. From the **Tools** panel, drag this toolset onto the canvas and connect it to the Agent Core.
3. To let the same agent also search indexed content, add a node from the **Knowledge** panel and connect that too.

The agent chooses which tool to call from the descriptions above, so a clear instruction such as "create an issue titled X" routes better than a vague one.
