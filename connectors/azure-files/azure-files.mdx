Azure File Shares is Microsoft's cloud version of a shared network drive, the kind your company might call the "S: drive" or "team share". This connector brings the files from your shares into PipesHub, so you can search them and ask questions about them in chat. PipesHub only reads your files. It never changes, moves or deletes anything in Azure.

<Warning>
  PipesHub does not copy the share or folder permissions you set in Azure. Who can search the synced files depends only on how you set up the connector:

  - **Team connector**: everyone in your organization can search every file it syncs. Use it only for shares the whole organization may read.
  - **Personal connector**: only you can search the files.
</Warning>

## Before you start

- An Azure account that can open the storage account that holds your file shares. A **storage account** is your top-level Azure storage; a **file share** is one shared drive inside it.
- One way for PipesHub to sign in to Azure. Pick one:
  - **A SAS connection string** (recommended). A SAS (shared access signature) is a password-like key that you limit to reading and listing files, and that stops working on a date you choose. Creating one needs a role that can see the storage account's keys, such as Owner or Contributor.
  - **Microsoft Entra ID**. PipesHub signs in as an app you register in Azure, with the **Storage File Data Privileged Reader** role. You need the rights to register apps and assign roles.
- A PipesHub account that can add connectors.

## Step 1: Get a credential in Azure

<Tabs>
<Tab title="SAS connection string (recommended)">

<Steps>
  <Step title="Open your storage account">
    Go to [portal.azure.com](https://portal.azure.com), sign in, search for **Storage accounts** and open the one that holds your file shares.
  </Step>
  <Step title="Open Shared access signature">
    In the left menu, click **Security + networking**, then **Shared access signature**.
  </Step>
  <Step title="Choose what the SAS allows">
    - **Allowed services**: tick **File** only.
    - **Allowed resource types**: tick **Service**, **Container** and **Object**.
    - **Allowed permissions**: tick **Read** and **List** only.
    - **End**: pick the date the SAS stops working. After that date, syncing stops until you paste a new connection string.
  </Step>
  <Step title="Copy the connection string">
    Click **Generate SAS and connection string**, then copy the **Connection string**. Keep it somewhere safe; Azure shows it only once.
  </Step>
</Steps>

</Tab>
<Tab title="Microsoft Entra ID">

<Steps>
  <Step title="Register an app">
    In the Azure portal, open **Microsoft Entra ID** → **App registrations** → **New registration**, give the app a name and register it. On the app's **Overview** page, copy the **Directory (tenant) ID** and the **Application (client) ID**.
  </Step>
  <Step title="Create a client secret">
    In the app, open **Certificates & secrets** → **New client secret**. Copy the secret's **Value** right away; Azure hides it later.
  </Step>
  <Step title="Give the app read access">
    Open your storage account → **Access control (IAM)** → **Add role assignment**. Choose the **Storage File Data Privileged Reader** role and assign it to the app.
  </Step>
  <Step title="Copy the file endpoint">
    On the storage account, open **Settings** → **Endpoints** and copy the **File service** address. It looks like `https://<account>.file.core.windows.net`.
  </Step>
</Steps>

<Note>
  Azure may not let an Entra ID app list the shares in a storage account. If the **File Share Names** list stays empty in Step 2, PipesHub can't find your shares this way; use a SAS connection string instead.
</Note>

</Tab>
</Tabs>

<Accordion title="Using an account key connection string instead">
  An account key connection string also works, but it gives full read, write and delete access to everything in the storage account. Use it only if you can't create a SAS.

  1. Open your storage account and click **Security + networking** → **Access keys**.
  2. Under **key1**, click **Show** next to **Connection string**, then copy it.

  <img
    src="/images/connectors/azure-files/storage_account_access_keys.png"
    alt="Azure portal Access keys page with the key1 connection string and its Show button"
    style={{ display: 'block', margin: '0 auto' }}
    width="95%"

  If someone later rotates the key in Azure, syncing stops until you paste the new connection string.
</Accordion>

<Warning>
  Treat the connection string and client secret like passwords. Don't paste them into chat, email or a shared file.
</Warning>

## Choose what to sync

All of these are on the **Configure records** tab. Add a sync filter with **Add filter**, and remove it with **Clear**.

| Setting | What it does |
|---------|--------------|
| **Sync strategy** | **Scheduled** syncs on its own. **Manual** syncs only when you start it. |
| **Sync interval** | How often a scheduled sync runs. 1 hour is the default. |
| **Enable Manual Indexing** | **Off** (default): every synced file becomes searchable. **On**: files are synced but not made searchable until you choose them. |
| **File Share Names** | Pick the shares to sync, or the shares to skip. Leave it empty to sync every share the credential can see. Search matches the start of a share name. |
| **Folders** | Sync only some folders (**In**) or skip them (**Not In**). Type each folder as a path from the top of the share, such as `reports/2026`, and press Enter. Leave it empty to sync the whole share. |
| **File Extensions** | Sync only some file types, such as `pdf` and `docx`, or skip some, such as images. |
| **Modified Date** | Sync only files changed before, after or between dates. |
| **Created Date** | Sync only files created before, after or between dates. |

<Tip>
  Filters make the first sync faster. On a team connector, use **File Share Names** to pick only the shares your whole organization may read.
</Tip>

The file type and date filters never hide folders, so the folder tree in PipesHub stays complete.

## What gets synced and how it stays up to date

- **What you get**: the files and folders in the shares you picked, with their folder structure. Documents (PDF, Word, PowerPoint, Excel, OpenDocument, RTF, EPUB), text files (TXT, Markdown, CSV, JSON, XML, HTML), code files and images (JPG, PNG, WebP) are searchable by their content. Other files, such as video, audio, GIFs and ZIP archives, are found by name only.
- **How often**: on your sync interval, or when you start a sync. The first sync reads everything and can take hours for a big share. Later syncs only process what changed, so they are much faster.
- **Edits**: changed files are refreshed on the next sync.
- **Moves and renames**: a moved or renamed file or folder keeps its place in PipesHub and is not processed again. Renaming a folder carries everything inside it along.
- **Deletes**: files, folders and shares you delete in Azure disappear from PipesHub on the next sync. So do files a new filter leaves out, and shares you take out of **File Share Names**.
- **Safe on errors**: PipesHub removes files only after it has read a whole share. If a share can't be read, or Azure refuses the credential, nothing is removed and you get a notification. The next sync tries again.
- **Opening files**: search results and citations open the file inside PipesHub, not in the Azure portal.
- **Not synced**: Azure share permissions and folder (NTFS) permissions. Blob containers in the same storage account; use the [Azure Blob connector](/connectors/azure-blob/azure-blob) for those.

## Troubleshooting

<AccordionGroup>

<Accordion title='Saving fails with "The AccountKey in the connection string is not a valid storage account key"'>
  The connection string has extra spaces or got cut off when you copied it. Copy it again from Azure and paste it fresh.
</Accordion>

<Accordion title='Sync does not turn on: "the credential needs the ... permission"'>
  The message names what the credential is missing:

  - **List (service level)**: it can't list the storage account's shares. Pick your shares in **File Share Names**, or create a SAS with the **Service** resource type.
  - **List**: it can't list a share. Create a SAS with the **List** permission and the **Container** resource type.
  - **Read**: it can't read files. Create a SAS with the **Read** permission and the **Object** resource type.

  With Microsoft Entra ID, check that the app has the **Storage File Data Privileged Reader** role on the storage account.
</Accordion>

<Accordion title='It used to work, but now I get "Credentials rejected"'>
  The SAS has expired, someone rotated the account key, or the Entra ID client secret changed or expired. Nothing synced so far is removed.

  Create a new credential (Step 1). In PipesHub, open the connector, click **Manage configuration**, paste the new credential on the **Authenticate** tab and save. Files you open in PipesHub before then ask you to reconnect the connector.
</Accordion>

<Accordion title="My shares don't appear in the File Share Names list">
  - Type the beginning of the share's name; the search matches from the start.
  - Check that the storage account has **file shares**, not only blob containers.
  - With Microsoft Entra ID, Azure may not allow listing shares. Use a SAS connection string instead.
  - The storage account may have a firewall. Ask your Azure admin to allow PipesHub to reach it.
</Accordion>

<Accordion title="Sync is on but no files appear">
  - Give the first sync time; large shares take a while.
  - Check your filters. Together they may leave nothing to sync.
  - If you get a notification that a share couldn't be read, check the credential's permissions on that share.
</Accordion>

<Accordion title="A file shows up but its content isn't searchable">
  - Video, audio, GIFs and archives are found by name only.
  - Password-protected and copy-protected (DRM) files can't be read.
  - If **Enable Manual Indexing** is on, choose the file for indexing first.
  - Large files take longer to process; check again later.
</Accordion>

</AccordionGroup>

<Accordion title="Details for administrators">
  - **Permissions**: the connector only lists and reads. A SAS needs the File service, the Service, Container and Object resource types, and the Read and List permissions. Entra ID needs the Storage File Data Privileged Reader role on the storage account. A SAS made for the File service only does not work for the Azure Blob connector, but an account key connection string works for both.
  - **Connection test**: when sync is turned on, PipesHub lists the shares (only if **File Share Names** is empty), lists the top folder of each selected share, and reads one file. A selected share that no longer exists does not block sync; the next sync removes its files and sends one notification. Remove the share from the filter if it is gone for good.
  - **Endpoints**: the connection string's file endpoint and the **File Endpoint** field must be public `https://` addresses. Plain `http` and private network addresses are refused when you turn sync on.
  - **Failures during a sync**: if one share or folder can't be read, its files are kept, the other shares still sync, and you get a notification naming the share. If no share can be read, or the share list can't be read, the sync is marked as failed. Throttled requests are retried.
  - **Storage**: PipesHub stores the connection string and client secret encrypted, and never shows them in logs or to other users.
  - **References**: [Azure Files](https://learn.microsoft.com/azure/storage/files/), [shared access signatures](https://learn.microsoft.com/azure/storage/common/storage-sas-overview), [connection strings](https://learn.microsoft.com/azure/storage/common/storage-configure-connection-string), [Entra ID for Azure Files over REST](https://learn.microsoft.com/azure/storage/files/authorize-oauth-rest).
</Accordion>
