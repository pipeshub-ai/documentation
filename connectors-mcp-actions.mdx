PipesHub gives your people and your AI agents three ways to work with company apps. They are easy to mix up because they all touch the same apps, but they do different jobs.

- **Connectors** copy content from an app into PipesHub's index, so it can be searched.
- **MCP** is a protocol. PipesHub uses it in two directions: it exposes its index to outside AI clients, and it lets your agents call other MCP servers.
- **Actions** let an agent do something in an app, such as send a message or create a ticket.

## The short version

| | Connectors | PipesHub as an MCP server | MCP servers your agents use | Actions |
|---|---|---|---|---|
| **What it does** | Syncs an app's content into PipesHub | Lets Claude Code, Cursor and other clients search and chat over your index | Gives an agent tools from another MCP server | Lets an agent act in an app |
| **Where the data is** | Indexed in PipesHub (search index and knowledge graph) | The same PipesHub index | Stays on the remote server | Stays in the app |
| **How fresh** | As fresh as the last sync (it runs on a schedule, not in real time) | As fresh as the index | Live on every call | Live on every call |
| **Who can see what** | Source permissions are stored with each record and applied at search | Applied per user at search | Whatever the remote server's sign-in allows | Whatever the user's own sign-in to the app allows |
| **Can it change things in the app** | No. It only reads. | Mostly no. Creating collections, uploading files and adding a web source need extra scopes. | Whatever the server offers | Yes |
| **Set up under** | [Connectors](/connectors/overview) | [MCP Server](/mcp/overview) | [MCP servers in agents](/agent-guide/mcp-servers) | [Actions](/toolsets/overview) |

## Connectors: search a copy of your company's content

A connector signs in to an app, reads its content and keeps a copy in PipesHub. The copy is indexed for search and linked in a knowledge graph. Each record keeps the permissions the app recorded, so a person sees only what the app already lets them see.

Because search runs on the copy, one question can search Slack, Drive, Jira and Confluence together, and it does not call those apps at question time. The tradeoff is freshness: a change in the app shows up after the next sync. See [Connectors](/connectors/overview).

## MCP: a protocol with two directions

[MCP](https://modelcontextprotocol.io) (Model Context Protocol) is a standard way for an AI client to call tools. PipesHub uses it two ways.

- **PipesHub as an MCP server.** An outside client such as Claude Code or Cursor connects to PipesHub and calls tools like search and chat. They query the same index the connectors built, as the signed-in user, so permissions apply. Which tools a token is offered depends on its scopes. See [MCP Server](/mcp/overview) and [Tools reference](/mcp/tools).
- **MCP servers in your agents.** An agent you build in PipesHub can call tools on another MCP server. Those calls run live against that server, and PipesHub does not index what comes back. See [MCP servers in agents](/agent-guide/mcp-servers).

## Actions: do things in an app

An Action is a task an agent can run in an app, such as sending a Slack message, creating a Jira issue or adding a calendar event. Each person signs in to the app with their own account, so an agent acts with that person's access. Actions run live and do not index anything. See [Actions overview](/toolsets/overview) and [API actions](/agent-guide/api-actions).

## A direct MCP server is not a connector

Many apps ship their own MCP server. An agent can call it directly, and for a change that happened a minute ago, or for a task such as posting a message, that is the right tool. For searching what your company knows, it behaves differently from a PipesHub connector:

- **Each call goes to one app.** A question that spans Slack, Jira and Drive needs several tool calls, one app at a time. A PipesHub index answers it with one search.
- **The agent reads more.** With only live calls, the agent makes more lookups and reads more text before it can answer.
- **Permissions are the server's own.** With the index, PipesHub applies each record's stored permissions in one place.

In PipesHub's own test, the same Claude model answered 100 work questions with each app's official connector, and then with one PipesHub index. The index found more of the required facts for every model, and answered faster and for less money. See [Direct MCP vs the PipesHub index](/benchmarks/mcp-vs-index) for the method, the numbers and the caveats.

## Which one should I use?

| I want to… | Use |
|---|---|
| Ask a question that needs several apps | [Connectors](/connectors/overview), then chat or search |
| Give Claude Code or Cursor my company's knowledge | [PipesHub as an MCP server](/mcp/overview) |
| Make an agent post, create or update something in an app | An [Action](/toolsets/overview) |
| Reuse a tool from another MCP server inside an agent | [MCP servers in agents](/agent-guide/mcp-servers) |
| See what changed in the last minute | A live Action or MCP call, since an index is a copy |

<Note>
  Actions are called toolsets in a few places in the API and in the code. In the product and in these docs they are Actions.
</Note>
