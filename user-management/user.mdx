The **Users** page lists everyone who has been invited to or is part of your workspace. Administrators can invite new members, manage existing ones, and act on pending invites from a single view.

## Navigating to Users

1. Sign in to your PipesHub account with administrator credentials
2. Open the user menu and click **Workspace settings**
3. In the workspace sidebar, expand the **People** section and select **Users**

The page shows a table of all workspace users with the following columns:

| Column | Description |
|--------|-------------|
| **User** | Avatar, display name, and email |
| **Role** | `Admin` or `Member` |
| **Status** | `Active`, `Pending`, or `Blocked` |
| **Last active** | Date of the user's most recent activity |
| **Date joined** | Date the user was added or invited |

Use the **search** field in the header to look up users by name or email, and the **filters** above the table to narrow results by status, last active date, or date joined. Clicking any row opens that user's **profile** panel on the right.

## Inviting Users

1. On the **Users** page, click the **Invite** button in the top-right corner
2. The **Invite users** panel opens on the right
3. In the **Invite to** field, type or paste one or more email addresses (separated by comma, space, or Enter). Invalid addresses are flagged inline
4. Under **Assign role**, choose the role for the new users (**Member** by default)
5. Click **Send invite**

<Note>
  **Invite** stays disabled until email is set up. Its tooltip says "SMTP is not configured. Set up email settings before inviting users." See [SMTP](/smtp).
</Note>

Each invited user receives an email with instructions to join the workspace. Until they sign in, their status on the Users page is **Pending**.

## Managing Pending Invites

Click the row actions menu (**⋯**) next to a user with status **Pending** to access invite-specific actions:

- **Resend invite** — Sends a fresh invitation email to the same address.
- **Edit invite** — Changes the role on the pending invite.
- **Cancel invite** — Revokes the outstanding invitation.

If an invitation expires, the same **Resend invite** and **Cancel invite** options appear so you can extend or revoke the invite.

<Note>
  **Sent an invite to the wrong address?** Cancel it and invite the right address. An admin cannot change the email address on someone else's account — see [Email addresses](#email-addresses) below.
</Note>

## Bulk Actions

Select one or more rows using the checkboxes. A floating action bar appears at the bottom of the table:

- If every selected row is a **Pending** invite: **Resend invite** or **Cancel invite**.
- Otherwise: **Remove from workspace** (disabled when the selection contains any Admin).

## Email addresses

An account's email address can only be changed by the person who owns the account, from their own profile. When they request a change:

- a confirmation link is sent to the **new** address, and the change takes effect only when that link is opened;
- a notice is sent to the **current** address saying which address the account is moving to and what to do if the request was not theirs.

Admins can edit a user's name, designation and role, but not their email address. The reason is that connector permissions follow the address: whichever account carries `alice@company.com` sees what Alice is allowed to see in the connected sources. Letting anyone else move an account between addresses would let them sign in as that person. To correct a wrong address on an invitation that has not been accepted yet, cancel the invitation and invite the right address.

## Managing Active Users

For an active (non-admin) user, the row actions menu offers:

- **View profile** — Opens the user's profile panel on the right
- **Change role** — Switches the user between Admin and Member
- **Remove from workspace** — Permanently removes the user. A confirmation dialog asks you to confirm.

Admin users expose **View profile** and **Change role**; to remove an admin, demote them to Member first.

## Unblocking Users

A user is **Blocked** after ten wrong passwords or codes in a row. The lock lifts by itself after 24 hours, and an admin can lift it sooner: open the row actions menu and choose **Unblock**. A confirmation dialog asks you to type the user's display name before the action is applied. See [How sign-in protects accounts](/auth#how-sign-in-protects-accounts).

## Removing a User

1. Open the row actions menu (**⋯**) for the user
2. Click **Remove from workspace**
3. In the confirmation dialog, click **Remove**

<Warning>
  Removing a user is immediate. They lose access to the workspace. Admin accounts cannot be removed until they are demoted to Member.
</Warning>
