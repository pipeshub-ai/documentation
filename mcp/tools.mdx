Reference for the tools exposed by the PipesHub MCP server. These tools let an AI client (Cursor, Claude Code, Gemini CLI, Claude.ai, LibreChat, etc.) talk to PipesHub: search and chat over the org's indexed documents, look up people and groups, download files, and talk to configured PipesHub agents.

The server exposes **eleven** tools: the seven below plus the four in [Filling a workspace](#filling-a-workspace). When the signed-in user has an indexed code repository and the token holds `code:read`, it also offers the ten [`pipeshub_code_*` tools](#code-graph-tools). Each tool wraps several lower-level API calls so the LLM gets a single, well-shaped response. This page follows the package's [TOOLS.md](https://github.com/pipeshub-ai/mcp-server/blob/main/TOOLS.md).

<Note>
  Searching and reading records (`pipeshub_search`, then `pipeshub_get_record_content`) is the recommended default for a client that can call tools. `pipeshub_chat` is optional: use it when the client cannot run its own search-and-read loop, when you want PipesHub's own assistant to write the answer, or to talk to a configured agent. On the local server, set `PIPESHUB_MCP_CHAT=off` to leave it (and `pipeshub_agents`) out.
</Note>

## `pipeshub_chat`

**Optional.** Ask PipesHub's own assistant a question and get an answer grounded in the org's indexed sources and the live web, with citations. It reads a **few retrieved passages**, never a whole document or a complete list.

<Warning>
  Plain chat can also take actions. It runs PipesHub's assistant with the actions the user has connected (for example creating a Jira ticket or sending an email), using the user's own credentials, unless an admin turned actions off. The tool is annotated `destructiveHint: true`, so clients that confirm risky calls ask first. Do not ask it to write unless the user asked for that action.
</Warning>

| Argument | Description |
|---|---|
| `query`<br/>*string, required* | The user's question or message for this turn. |
| `conversationId`<br/>*string, optional* | Existing conversation id to continue. Omit on the first turn; pass it back on every subsequent turn. |
| `filters`<br/>*object, optional* | Source scoping: `{ apps, kb }`. Connector ids go in `apps`, collection ids go in `kb`; get both from `pipeshub_sources`. Leave out to use all sources. Only works on the first turn. |
| `modelKey`<br/>*string, optional* | Model id from `pipeshub_sources` `llmModels[*].modelKey`. Defaults to the org's default LLM. |
| `agentId`<br/>*string, optional* | PipesHub agent to converse with (`agentId` from `pipeshub_agents`). Pass the same `agentId` on every follow-up turn. Omit for plain chat. |

**Check these three questions first. Chat gets them wrong:**

- **Structure**: "what's under this epic?", "which pages are in this space?", "what's in this folder?" → `pipeshub_get_record_content` `mode:"navigate"`.
- **Exhaustive**: "how many X?", "list all the Y", "every Z" → `mode:"navigate"`. Chat undercounts and will not say so.
- **One named document**: summarize it, extract from it, what does it say about X → `pipeshub_search` for the `recordId`, then `mode:"content"`.

For other questions about the org's knowledge, including ones that span several documents, search and read the records yourself unless the user asks for PipesHub's own answer.

**Response:** the AI's `answer`, `citations[]`, `claims[]`, `uncitedSentences[]`, `followUpQuestions`, plus the `conversationId` to use for follow-ups. `notes[]` appears when the tool moved a scoping id to the right list or could not check the ids.

- Each citation has its `number` (the `[N]` in the answer), `recordId`, `recordName`, `webUrl`, and the cited text as `passage` (up to 1,500 characters; a longer text is cut and carries `passageTruncated: true`). `kind` says what the text is: `passage`, `matchedText`, `summary`, `recordName` or `web`.
- Each claim is one cited sentence, with its citation numbers and `quotes` copied from the cited text. `notInCitedText` lists IDs, numbers or dates the sentence states that none of its cited texts contain.
- `uncitedSentences` are sentences of four or more words with no citation.
- `warning` appears if the stream ended early: the `answer` is then the text received so far and citations are unavailable.

Treat the answer as a lead. Before stating a specific ID, status, date or owner, check it against the claim's quotes or confirm it in the cited record with `pipeshub_get_record_content` `mode:"content"`. If `citations` is empty, relay the answer as **unsourced and not confirmed**.

## `pipeshub_search`

Vector / semantic search across the org's indexed documents. It is the **default first step for a question about the org's knowledge**: search, then read the records that matter with `pipeshub_get_record_content`. It also **locates a document** by name, topic or phrase and resolves it to a `recordId`.

| Argument | Description |
|---|---|
| `query`<br/>*string, required* | Natural language query. |
| `limit`<br/>*number (1–100), optional* | Vector matches to fetch. Default 10. 5–10 is enough to find a `recordId`. |
| `offset`<br/>*number, optional* | Records to skip. To read the next page, pass the previous call's `nextOffset` with the same other arguments. |
| `apps`<br/>*string[], optional* | Connector ids to search, from `pipeshub_sources` where `kind` is `"connector"`. |
| `kb`<br/>*string[], optional* | Collection ids to search, from `pipeshub_sources` where `kind` is `"knowledgeBase"`. |
| `createdAfter` / `createdBefore`<br/>*string, optional* | Only records created in their source within these dates. `YYYY-MM-DD` (whole day, UTC) or an ISO 8601 datetime with a timezone. Inclusive. |
| `modifiedAfter` / `modifiedBefore`<br/>*string, optional* | Only records last changed in their source within these dates, same format. |
| `timeline`<br/>`"created"` \| `"modified"` \| `"off"`, *optional* | Search a span period by period, for how something evolved or a summary over months. Each page holds every period's best records, oldest first, each with its `period`. `"off"` forces one ranked search. |

Leave out `apps` and `kb` to search everything; if you set either, only the listed sources are searched. The date filters match when a record was written or last changed at its source, not the date of an event it describes, so leave them off unless the question is about when records were written.

**Response:** `records[]`, one entry per record, best match first: `recordId`, `recordName`, `recordType`, `connector`, `webUrl`, `createdAt` / `updatedAt`, `parent` (the channel, space or project it sits in), `status` (for a ticket or pull request), `links` (up to 3 related records), `score`, `passagesFound` and up to 3 `passages` (each `text` is at most 350 characters). Also `totalRecords`, `outsideDates` (best matches written outside your date bounds, when a dated search found some) and `notes[]`. A result stays under 20,000 characters; when records were left out, `nextOffset` is set.

Records are a ranked sample, never a complete list. Never count them to answer "how many" / "all" / "every"; use `mode:"navigate"` instead.

## `pipeshub_get_record_content`

Four operations on records, selected by `mode`.

| Argument | Description |
|---|---|
| `mode`<br/>*enum, optional* | `content` (default), `thread`, `navigate`, or `lookup`. |
| `recordId`<br/>*string, conditional* | Required when `mode` is `content` or `thread`. Get it from a chat citation, a search hit, or a `lookup`. |
| `maxChars`<br/>*number (2000–140000), optional* | `content` and `thread`. Most characters of text to return. Default 40000. |
| `query`<br/>*string, optional* | `content` only. What you are looking for. When the record is longer than `maxChars`, the most relevant passages come back first. |
| `extract`<br/>*boolean, optional* | `content` only, with `query`. Return only the passages that answer `query`, copied word for word by PipesHub's reader model, instead of the record's text. Needs a newer PipesHub server; an older one ignores it. |
| `startBlock`<br/>*number, optional* | `content` and `thread`. Continue reading from the block named in the previous part's `Next:` line. |
| `startRecord`<br/>*number, optional* | `thread` only. Continue a long thread from this record, as the `Next:` line names it. |
| `nodeId`<br/>*string, optional* | `navigate` only. Omit to list the top level: a flat listing of everything reachable. On a limited connection, see the note below. |
| `page` / `limit`<br/>*number, optional* | `navigate` only. 1-based page, 50–200 children per page (default 50). |
| `depth`<br/>*number (1–3), optional* | `navigate` only. `2` or `3` flattens descendants into one call instead of one call per level. Default 1. |
| `nodeTypes`<br/>*string[], optional* | `navigate` only. List only children of these node types, for example `["record", "folder"]`. |
| `createdAfter` / `createdBefore`, `modifiedAfter` / `modifiedBefore`<br/>*string, optional* | `navigate` only. List only children created or last changed in their source within these dates. `YYYY-MM-DD` or an ISO 8601 datetime with a timezone offset. |
| `identifiers`<br/>*string or string[], conditional* | Required when `mode` is `lookup`. A URL, issue key, or external ID, or up to 10 of them. |
| `connectorName`<br/>*string, optional* | `lookup` only. Try this connector first, for example `JIRA` or `CONFLUENCE`. It does not widen the lookup beyond the connectors you can access. |

- **`mode: "content"`**: The only way to see a document's full text. Use it to summarize, extract, or quote a named document. A long record comes back in parts, each ending with a `Read:` line and, while text is left, a `Next:` line naming the call that reads on. Pass `query` with `extract: true` to pull a few facts out of a long record for less context.
- **`mode: "thread"`**: Every message of the Slack thread that `recordId` belongs to, parent first, limited to what the caller may see. A Slack record is one burst of messages; replies are separate records (`Reply Count: N` means they are not included), so use this mode to read them.
- **`mode: "navigate"`**: Browse the hierarchy (project / space / folder → records → children). Use it for structure and for every "how many" / "all" / "every" question. Pass `depth: 2` or `3` to see several levels in one call. Returns no document text.
- **`mode: "lookup"`**: Resolve a Jira key, URL, or external ID to a `recordId` plus metadata.

**On a limited connection.** A personal access token or OAuth app set to **Only what I pick** browses only what was picked. With no `nodeId`, `mode: "navigate"` lists:

- **Whole sources only:** the flat listing above, kept to those sources: every record group (project, space, drive, channel) and every record (issue, page, message, file) in them. Its total mixes the two, so don't read it as a count of issues, pages, messages or files.
- **Any space, folder or file picked:** one item for each source, space, folder and file picked, and nothing inside them. `pagination.total` counts these items, not what they hold, and `depth` does not open them. To see inside an item, pass its id as `nodeId`. Do that for each item before answering a "how many" or "list all" question.

## `pipeshub_download_record`

Stream the binary content of a single record. Use it when the user wants the actual file bytes (download, attach, open).

| Argument | Description |
|---|---|
| `recordId`<br/>*string, required* | From a chat citation or `pipeshub_search` hit. |
| `convertTo`<br/>*string, optional* | Optional server-side conversion. The only supported target is `application/pdf` (a bare `pdf` is ignored with no error). Omit for the file as stored. |

## `pipeshub_directory`

Look up people, groups, and teams. One tool with five `action`s.

| Argument | Description |
|---|---|
| `action`<br/>*enum, required* | One of `whoami`, `list_users`, `get_user`, `list_groups`, `list_my_teams`. |
| `userId`<br/>*string, conditional* | Required when `action` is `get_user`. |
| `page`<br/>*number, optional* | 1-based page number for `list_*` actions. |
| `limit`<br/>*number (1–100), optional* | Items per page for `list_*` actions. |
| `search`<br/>*string, optional* | Substring match against name / email. Used by `list_users` (including find-by-email). |

## `pipeshub_sources`

Discover available chat sources and AI models in one call. Call this once at the start of a session and cache the result.

| Argument | Description |
|---|---|
| `include`<br/>*enum[], optional* | Default: `["sources", "llmModels"]`. Add `"embeddingModels"` if configuring re-embedding. |

Each source `id` is the value to put in `pipeshub_chat`'s or `pipeshub_search`'s `apps` filter.

## `pipeshub_agents`

List the PipesHub **agents** configured for this org. To converse with one, take its `agentId` and pass it to `pipeshub_chat`.

| Argument | Description |
|---|---|
| `search`<br/>*string, optional* | Case-insensitive match on the agent's name, description and tags. Omit to list every agent. |

**Route on `toolsets` / `knowledge`, not the name.** (`toolsets` lists the agent's actions; the API still calls them toolsets.) Match the request to the agent whose tools can actually perform it. The list may be empty. For plain Q&A, use `pipeshub_chat` without `agentId`.

## Filling a workspace

Four tools take an empty workspace to a searchable one. The two that write, `pipeshub_create_collection` and `pipeshub_upload`, need the `kb:write` and `kb:upload` scopes. On a new install, personal access tokens and agent logins get them by default; on an upgraded instance, see [Customizing Default Scopes](/mcp/overview#customizing-default-scopes). A token without them is not offered those two tools. The local stdio server leaves them out with `--scope read`.

### `pipeshub_create_collection`

Creates an empty collection that the caller owns, to upload into. Names are not unique: to add to an existing collection, use its id from `pipeshub_sources`.

| Argument | Description |
|---|---|
| `name`<br/>*string, required* | 1–255 characters. |

Returns `{ collectionId, name, url }`.

### `pipeshub_upload`

Uploads documents into a collection. Each document travels inline: `text` for text formats, `base64` for binary ones. Up to 20 documents and about 3 MB per call. For a folder or larger files, run the CLI: `pipeshub upload <collectionId> <path>`, after signing it in with `pipeshub login`.

| Argument | Description |
|---|---|
| `collectionId`<br/>*string, required* | From `pipeshub_create_collection` or `pipeshub_sources`. |
| `documents`<br/>*array, required* | 1–20 items, each `{ name, text }` or `{ name, base64 }`. The extension in `name` sets the type: pdf, docx, pptx, xlsx, md, txt, html, csv, json, png, jpg and more. |

Returns `{ uploaded, failed, summary }`. Indexing follows in the background.

### `pipeshub_indexing_status`

Reports how far a collection's records are through indexing. Poll it every 15–30 seconds after an upload until `done` is true; search finds a document only once it is indexed. Counts are exact at any collection size.

| Argument | Description |
|---|---|
| `collectionId`<br/>*string, required* | The collection to check. |

Returns `{ done, total, pendingCount, failedCount, pending, failed }`. `pending` and `failed` list up to 25 records each; failed records carry the reason.

### `pipeshub_connect_source`

Returns the page where the user connects Slack, Google Drive, Jira or another source. Connecting needs the user's own sign-in in a browser, so the agent hands over the link.

| Argument | Description |
|---|---|
| `connector`<br/>*string, optional* | Opens that connector directly, e.g. `Jira`. |

Returns `{ url, adminUrl, instructions }`. Give the user `url`: it opens their personal connectors page. `adminUrl` opens the organization's connectors page and works only for an admin connecting the source for everyone; anyone else is redirected to their personal page without the connector selected.

## Code graph tools

<Note>
  These tools are experimental. They appear only when the caller's OAuth token or personal access token holds the `code:read` scope and the user has at least one indexed code repository. Each checks the caller's access to every record it returns.
</Note>

| Tool | Use it to |
|---|---|
| `pipeshub_code_repos` | List the indexed repositories you can read. Every other code tool takes one of these names as `repo` (`owner/name`). |
| `pipeshub_code_symbols` | See what a directory or file in a repo holds. |
| `pipeshub_code_neighbours` | Find callers, callees, imports and inheritance of a file or symbol. |
| `pipeshub_code_read` | Read indexed source: one symbol, or a line range. |
| `pipeshub_code_path` | Show how symbol A reaches symbol B, hop by hop. |
| `pipeshub_code_search` | Find code without knowing its file, by identifier, text or regex. |
| `pipeshub_code_semantic_search` | Find code by what it does when you do not know its names. Results are ranked by meaning. For a name you know, use `pipeshub_code_search`. |
| `pipeshub_code_outline` | List a file's symbols with line ranges, no bodies. Read this before `pipeshub_code_read`. |
| `pipeshub_code_impact` | See what changing a symbol can break. |
| `pipeshub_code_entry_points` | Find where control enters a repo: routes, CLIs, jobs. |

Cross-file call and import edges are resolved for Python, JavaScript, TypeScript and Java; other languages get calls matched by name. A `coverage` field in a result says when an answer may be incomplete, so confirm an empty result with `pipeshub_search`.

## Required scopes

| Scope | Tools |
|---|---|
| `semantic:write` | `pipeshub_search` |
| `conversation:chat` | `pipeshub_chat` |
| `agent:read`, `agent:execute` | `pipeshub_agents`, `pipeshub_sources`, `pipeshub_chat` with an agent |
| `kb:read`, `connector:read`, `config:read` | `pipeshub_sources`, `pipeshub_get_record_content`, `pipeshub_download_record`, `pipeshub_indexing_status` |
| `kb:write`, `kb:upload` | `pipeshub_create_collection`, `pipeshub_upload` |
| `user:read`, `team:read`, `usergroup:read` | `pipeshub_directory` |
| `code:read` | The `pipeshub_code_*` tools |

`offline_access` is not a tool scope: it lets the client keep a refresh token. See [Customizing Default Scopes](/mcp/overview#customizing-default-scopes).

## Quick Decision Guide

| User says... | Use this tool |
|---|---|
| "What does the Q4 report say about ARR?" | `pipeshub_search` → top hit → `pipeshub_get_record_content` |
| "Summarize the onboarding doc" | `pipeshub_search` → top hit → `pipeshub_get_record_content` |
| "What do we know about X?" (spans many docs) | `pipeshub_search` → read the records that matter with `pipeshub_get_record_content` |
| "What's our PTO policy?" (no single named file) | `pipeshub_search` → read the top records with `pipeshub_get_record_content` |
| The client cannot run its own tool loop, or wants PipesHub's own answer | `pipeshub_chat` |
| "How many / list all / every X" | `pipeshub_get_record_content` `mode:"navigate"`, not chat |
| "Find the file called *security-review.pdf*" | `pipeshub_search` |
| "Download that file" | `pipeshub_download_record` |
| "Who am I?" | `pipeshub_directory` (`whoami`) |
| First call of a session | `pipeshub_sources` (cache the result) |
| "Index these docs" / the workspace is empty | Reuse the collection the user means (`pipeshub_sources`, `kind: "knowledgeBase"`), or `pipeshub_create_collection` if there is none → `pipeshub_upload` → `pipeshub_indexing_status` → `pipeshub_search` |
| "Connect our Jira / Slack / Drive" | `pipeshub_connect_source`, then give the user `url` (`adminUrl` only if they are an admin connecting it for the organization) |
| "Create a Jira ticket" / talk to a configured agent | `pipeshub_agents` → `pipeshub_chat` with that `agentId` |
| "Where is X defined?" / "who calls Y?" in an indexed repo | `pipeshub_code_repos`, then the other `pipeshub_code_*` tools |
